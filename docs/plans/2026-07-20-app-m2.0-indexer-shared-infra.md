## 1. Origin & problem statement

M1 delivered the indexer as a heartbeat supervisor
([`services/indexer/src/index.ts`](../../services/indexer/src/index.ts)) that
proves its DB connection and idles — "the shape M2 workers slot into." The four
M2 workers (2.1–2.4) and the reconciler (2.5) each need the same primitives:

- a **block-window transaction** that advances the durable cursor
  (`indexer_checkpoints`) atomically with the data it derived (spec §9.2 — the
  cursor "advances only after the full block window commits in one DB
  transaction");
- **RPC transports the shared LCD client lacks** — `block_results` (EndBlocker
  events), `tx_search`/`block_search`, and **height-pinned smart query** — since
  [`@nvhash/chain-client`](../../packages/chain-client/src) is grpc-gateway REST
  only today;
- a **JSON-string-stripping attribute decoder** (the manifest pins that vault
  event attribute *values* carry an extra quoting layer — `denom = "nvhash"`);
- **per-`(chain_id, contract)` isolation** so a devnet redeploy never mixes
  histories (spec §9.3).

If each worker reinvents these, they diverge on the one invariant that makes
replay correct, and they all edit the entrypoint. This PR lands them once.

## 2. Mechanism (fixed)

New files under `services/indexer/src/`:

- **`runtime/checkpoint.ts`** — `runWindow(stream, {from, to}, fn)`: opens one
  `prisma.$transaction`, invokes `fn(tx, window)` for all data upserts, then
  upserts `IndexerCheckpoint.cursorHeight = to` **inside the same transaction**.
  This is the single place the cursor-after-commit invariant lives; workers
  never write their checkpoint directly. Also `readCheckpoint(stream)` and
  confirmation-depth trailing (`target = head − depth`; depth from config,
  default 0 — Provenance instant finality, spec §9.2, resolves §14.5 depth).
- **`runtime/worker.ts`** — the loop shell (poll head → compute trailing target
  → page windows → `runWindow` → sleep → repeat) with crash-restart-from-
  checkpoint semantics and structured lag logging (`stream`, `chainHeight`,
  `indexedHeight`). Exposes `registerWorker()` so siblings don't each re-edit
  the entrypoint.
- **`runtime/streams.ts`** — canonical stream-name constants and the isolation
  boot check: on start, compare `config.chainId + config.contractAddress`
  against a persisted marker; on mismatch **fail loudly** (operator resets the
  DB with the chain, §9.3). Never silently append across chain/contract pairs.
- **`decode/attributes.ts`** — `attr(event, key)` returns the de-quoted string
  (tolerating both quoted `"nvhash"` and bare `EndBlock` values); `coinAttr`
  splits `"36852482nhash"` into `{ amount: bigint, denom }` via chain-client
  `parseCoin`/`parseUint128`. The pinned quoting fact lives in exactly one
  tested place.
- **`transport/rpc.ts`** — `blockResults(height)` (Tendermint
  `/block_results` → `finalize_block_events`), `txSearch(query, page)`,
  `blockSearch(query)`, and height-pinned smart query
  (`x-cosmos-block-height`). App-local, keeping `@nvhash/chain-client` REST-only
  and dependency-minimal (§6).

Minimal edit to **`src/index.ts`**: the supervisor starts registered workers and
supervises them (propagating fatal DB loss), instead of only pinging. Preserves
the heartbeat contract (`scripts/healthcheck.mjs`), the no-HTTP / no-keys /
no-signing boundary (master plan §1), and clean-shutdown handling.

## 3. Security & invariant impact (enforced mechanisms with gating tests)

1. **Atomic cursor advance.** `runWindow` advances the checkpoint only if `fn`
   commits. *Gate:* unit test — a throwing `fn` leaves `cursorHeight` unchanged;
   a successful window advances it exactly to `to`.
2. **Quoting-layer decode correctness.** *Gate:* `decode/attributes.ts` unit
   test over real fixture attributes (quoted vault values + bare `mode`), proving
   one JSON-string layer is stripped and coin amounts parse to `bigint`.
3. **Chain/contract isolation.** *Gate:* boot-check unit test — a persisted
   marker mismatching config refuses to start.
4. **SECURITY.md.** No new Prisma columns → schema-allowlist gate
   (`test/security/allowed-fields.ts`) stays green untouched. Logging uses only
   `SAFE_FIELDS`. The new `transport/rpc.ts` is an in-repo transport (no new
   third-party dependency); record it under dependency discipline in CLAUDE.md.

## 5. Tests

- `test/runtime/checkpoint.test.ts` — atomicity (no advance on throw; exact
  advance on commit).
- `test/decode/attributes.test.ts` — quoted/bare stripping, `coinAttr` →
  `{ bigint, denom }`, against `packages/fixtures` attributes.
- `test/runtime/streams.test.ts` — isolation boot check.

All Postgres-free (checkpoint atomicity models the tx boundary or uses the
existing DB-backed config if a live tx is needed), so they join
`pnpm -r run test`.

## 1. Origin & problem statement

Master plan §2: *"epoch-history worker + genesis backfill → `epoch_snapshots`;
per-(chain_id, contract) isolation."* The `EpochSnapshot` model already exists
([`epoch_snapshots.prisma`](../../services/indexer/prisma/epoch_snapshots.prisma))
and mirrors the contract §9.10 decomposition plus gross/net APR bps — the exact
shapes captured in `@nvhash/fixtures`.

The pivotal constraint (`app-spec.md` §13, contract §9.10): the contract keeps
only the **latest** epoch snapshot in state — there is **no query-by-index**.
Program history exists only because the App indexes it. So historical backfill
is a **height-pinned smart query at each `run_epoch` crank height**: querying
`epoch_snapshot`/`apr` at height H returns the epoch that closed at H (the fixture
snapshot carries `epoch_index: 8`, `end_height: 7811`).

## 2. Mechanism

Files under `services/indexer/src/workers/epoch-history/`:

- `index.ts` — registers the `epoch-history` worker.
- `boundaries.ts` — scan a window for `wasm` events with `action = run_epoch`
  from `contractAddress` → the **crank heights**.
- `snapshot.ts` — for each crank height H, **height-pinned smart query**
  (M2.0 `transport/rpc.ts`) `epoch_snapshot` and `apr`, decoded via the existing
  `parseEpochSnapshot`/`parseApr` in `@nvhash/chain-client` (no rebuild). Map to
  an `EpochSnapshot` row = snapshot decomposition + `grossAprBps`/`netAprBps` +
  `txhash`/`height`/`observedAt`.
- `backfill.ts` — on first run (empty checkpoint) start the cursor at the
  **contract instantiation height** (discovered via the instantiate tx /
  `block_search` for the instantiate event, or config-provided) and walk forward
  to head.

### Idempotency & atomic cursor

Upsert by `epochIndex` (the model `@id`). The `epoch-history.cursorHeight`
advances to the window's `to` inside the same M2.0 `runWindow` transaction as
the snapshot writes. Re-pointing to 0 re-queries every crank height and
re-upserts identical rows — on-chain state at a past height is deterministic, so
convergence holds.

### Isolation

Per-`(chain_id, contract)` isolation via M2.0 `runtime/streams.ts`: refuse to
append to a history captured under a different chain/contract (devnet redeploy →
operator resets the DB with the chain, §9.3).

## 3. Security & invariants (enforced mechanisms with gating tests)

1. **Idempotent replay** (SECURITY.md chain-is-source-of-truth). *Gate:*
   `test/property/epoch-history-idempotency.test.ts` — a random set of crank
   heights → backfill → re-point from a random height → identical
   `epoch_snapshots` set (in-memory DB model, Postgres-free).
2. **Decode matches the corpus.** *Gate:*
   `test/fixture/epoch-snapshot-decode.test.ts` against
   `queries/contract/epoch-snapshot.json` + `apr.json`; boundary-detection unit
   test against `run-epoch/*.json` asserting `action = run_epoch` detection.
3. **Amount + signed discipline.** `netDeposits` is signed; all amounts already
   `Decimal(39,0)` in the model — the schema-allowlist amount check covers it.
   No new columns; no PII (public program history only).

## 6. Open questions

- **Height-pinned smart query home:** promote it into `@nvhash/chain-client`
  (shared, if the console will also height-pin) or keep it App-local in M2.0
  `transport/rpc.ts` (default — keeps the shared package REST-only). 2.2's
  reviewer makes the call explicitly.
- **Unrecoverable history caveat (document, don't hide):** height-pinned query
  works for any past height on a full-state chain; the only unrecoverable case
  is a chain that **pruned** state below the query height. Flag this as a
  config/retention caveat in the spec note, not a silent gap.

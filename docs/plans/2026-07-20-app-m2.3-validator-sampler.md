## 1. Origin & problem statement

Master plan §2: *"validator-sampler → `validator_registry`, `validator_epochs`
(uptime, eligibility, tip, commission, jail events)."* Both models exist
([`validator_registry.prisma`](../../services/indexer/prisma/validator_registry.prisma),
[`validator_epochs.prisma`](../../services/indexer/prisma/validator_epochs.prisma)).
Per contract §10, uptime is read on-chain from slashing `SigningInfo` (no
oracle); commission/TIP are program economics the contract tracks; jail is the
two-phase report/purge lifecycle (§9.8).

## 2. Mechanism

Files under `services/indexer/src/workers/validator-sampler/`:

- `index.ts` — registers the `validator-sampler` worker.
- `sample.ts` — reads a validator snapshot from: contract `validators()`
  (per-validator uptime/eligibility/tip/commission accrued·paid·due/jail) and
  `jailReports()`; **slashing `SigningInfo`** for uptime cross-check (a small
  `SlashingClient` reader — add to `@nvhash/chain-client` or local, §6); and
  `x/staking` for `moniker`/`programDelegation`.
- `registry.ts` — enrollment-lifecycle reducer → `ValidatorRegistry` (first-seen
  `enrolledAt`; `unregisteredAt` when a validator leaves the program set).
- `epochs.ts` — per-epoch row builder → `ValidatorEpoch`.

### Idempotency & epoch keying

- `validator_registry` upserts by `valoper` (the model `@id`).
- `validator_epochs` upserts by `(valoper, epochIndex)` (the model `@@id`).
  **Epoch is the sampling key, not wall-clock:** the sampler runs on a
  height/time cadence but keys every write to the *current* epoch index
  (detected via the same `run_epoch` signal M2.2 uses, or `epochStatus()`).
  Intra-epoch samples overwrite the current epoch's row (last-write-wins on the
  evolving accrual fields); the row is sealed at epoch roll, so prior epochs
  never mutate and repeated sampling converges to one row per `(valoper,
  epochIndex)`.

The cursor `validator-sampler.cursorHeight` advances with the write in one M2.0
`runWindow` transaction.

### Boundary with the reconciler

2.3 writes **facts only** (jail events, eligibility, arrears via
`commissionDue`). PR 2.5 turns those facts into `jail_report` incidents — a
clean single-writer boundary (2.5 is the sole writer of `incidents`).

## 3. Security & invariants (enforced mechanisms with gating tests)

1. **Convergent sampling.** *Gate:*
   `test/property/validator-sampler-convergence.test.ts` — repeated intra-epoch
   samples of a random validator set converge to a single `(valoper,
   epochIndex)` row set; an epoch roll seals rows without mutating prior epochs.
2. **Decode matches the corpus.** *Gate:*
   `test/fixture/validators-decode.test.ts` against
   `queries/contract/validators.json`, `jail-reports.json`,
   `queries/staking/validators.json`, `queries/staking/delegations.json`.
3. **No PII.** `valoper`/`operator`/`moniker` are public on-chain identifiers
   (already allowlisted); no IP/device, no off-chain identity. No new columns.

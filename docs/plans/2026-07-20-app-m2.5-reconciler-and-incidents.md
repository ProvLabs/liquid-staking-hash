## 2. Mechanism

Files under `services/indexer/src/reconciler/`:

- `index.ts` — a **separate loop** (stream `reconciler`) at its own slower
  cadence (~30s), **not** inside any worker's window transaction.
- `deltas.ts` — the §9.5.6 indexed-vs-live comparison.
- `tolerances.ts` — the per-metric tolerance table.
- `incidents.ts` — the §9.6 derivation → `Incident` upserts.
- `lag.ts` — per-stream `indexed_height` vs `chain_height`.

### Why a separate, independent loop

It reads the **live plane** (fresh `@nvhash/chain-client` smart queries / vault
state) and the **indexed plane** (latest `epoch_snapshots`,
`redemption_requests`, checkpoints) and compares. Keeping it independent is what
lets it be *"the alarm that survives an indexer outage"* (§12.1.3): if the
workers stall, the reconciler still runs, detects growing lag/divergence, and
opens incidents. It never presents a chain-contradicting number as current —
enforced by machinery, not review.

### Deltas (§9.5.6) → `reconciler_runs`

Per pass, compute and store one row (`ranAt`, `chainHeight`, `indexedHeight`,
`deltas` JSON, `withinTolerance`, `incidentId?`):

- **NAV inputs** — live vault NAV / `EventSetNetAssetValue` price vs indexed
  `navAtHeight` / latest snapshot `tvvAfter`.
- **Total shares** — live vault `total_shares` vs indexed
  `epoch_snapshots.totalShares`.
- **Epoch index** — live `epochStatus`/`epoch_snapshot.epoch_index` vs max
  indexed `epochIndex`.
- **Queue length** — live `pendingSwapOuts` count vs indexed non-terminal
  `redemption_requests`.

### Tolerances live in code, not config

`tolerances.ts` is a typed in-code constant table (per-metric absolute/relative
tolerance + the lag threshold), reviewed like the schema allowlist. It is
**not** env-tunable: a tolerance is a correctness contract, and env-tuning it
would let an operator silence the alarm, which §12.1.3 forbids. Referenced from
spec §9.5.6/§12.1 in the same change.

### Incident derivation (§9.6) → `incidents`

Map each condition to the existing `IncidentKind` enum (`contract_halted`,
`vault_paused`, `slash_write_down`, `redemption_refund`, `jail_report`,
`epoch_overdue`, `reconciler_divergence`, `indexer_lag`). **Open via upsert on
`(kind, dedupeKey)`** (the model `@@unique`) so re-derivation is idempotent —
e.g. `dedupeKey = epoch:{n}` (slash write-down), `request:{id}` (refund),
`stream:{name}` (lag). Closure is computed when the condition clears (`closedAt`
set). Severity per `IncidentSeverity`, aligned to console status semantics.

**2.5 is the sole writer of `incidents`** — it reads the facts the workers
persisted (refund/jail/slash-in-snapshot/halt-pause flags) and derives incidents
from them, so §9.6's *"computed from indexed facts, never hand-entered"* has
exactly one writer. The optional admin acknowledgment is an `app`-schema
`incident_acks` row (ADR-001) written by the web tier, never here.

### Lag accounting → the freshness envelope

`lag.ts` reads every stream's `IndexerCheckpoint.cursorHeight` vs the live head →
per-stream `indexed_height`/`chain_height`; max lag beyond `tolerances` opens an
`indexer_lag` incident and is the number `services/api`'s freshness envelope +
the DATA DEGRADED banner consume (§9.2/§9.4). The indexer **writes** rows; the
API **reads** them — no new HTTP surface in the indexer (master plan §1).

## 3. Security & invariants (enforced mechanisms with gating tests)

1. **The alarm actually fires** — the milestone's defining gate. *Gate:*
   `test/integration/reconciler-alarm.test.ts` (Postgres-backed, like the
   existing grant-boundary gate): seed an `epoch_snapshots`/`redemption_requests`
   row that diverges beyond tolerance from a mocked live read, run one
   reconciler pass, assert a `reconciler_divergence` `Incident` opens and
   `reconciler_runs.withinTolerance = false` with `incidentId` set. This is the
   unit-level precursor to the M8 8.1 degradation drills.
2. **Idempotent derivation.** *Gate:* re-running the same divergence upserts the
   same `(kind, dedupeKey)` incident — no duplicate row.
3. **Tolerance boundaries.** *Gate:* `deltas.ts` unit tests at tolerance edges
   (just inside → clean; just outside → incident).
4. **No PII; not env-silenceable.** `reconciler_runs`/`incidents` hold purely
   operational facts (allowlisted, no new columns). The tolerance table is
   in-code, so the alarm cannot be tuned away via environment.

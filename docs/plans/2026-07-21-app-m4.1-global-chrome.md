## 1. Origin & problem statement

Master plan §2: *"Global chrome: nav, banner slot (paused/halted/data-degraded),
environment badge, footer freshness line, verify-link component (per-figure
Console deep links, environment-locked), alerts bell placeholder."* This PR
gates 4.2–4.4; those pages render inside this chrome.

The PR 1.3 scaffold ships a minimal header (name + theme toggle) and a footer
(chain id + console link) in `apps/web/app/root.tsx`. This PR replaces both with
the full §8.0 chrome. Everything it needs already exists:

- **Live plane (§5.1):** `@nvhash/chain-client` parses both banner inputs.
  `paused`/`pausedReason` are on `VaultState` (vault `get`, `parseVaultState`);
  `halted` is on `EpochStatus` (contract `epoch_status` smart query,
  `parseEpochStatus`). Both are covered by the MSW fixture harness
  (`app/mocks/handlers.ts`), so the chrome builds and tests offline.
- **Indexed plane freshness:** `@nvhash/api-types` `Envelope`/`FreshnessMeta`
  (PR 1.2) with `chain_height`/`indexed_height: number | null`, where null is
  the honest "not yet known" state. `services/api` already serves
  `GET /api/v1/status` (enveloped, null heights until M3) and
  `GET /api/v1/incidents`.
- **Environment lock:** the `CONSOLE_CHAIN_ID = CHAIN_ID` boot check (PR 1.3,
  §12.2) already makes cross-environment verify links impossible; the component
  only consumes the booted `consoleUrl`.

One genuinely new config fact: the web tier has no base URL for `services/api`.
This PR adds server-only **`API_URL`** (zod-bounded in
`app/config/config.server.ts`, classified in `scripts/server-only-env.json`,
NOT added to the client-safe allowlist) and amends app-spec §7 in the same
change.

## 2. Mechanism

### Chrome state (server)

`app/chrome/chrome.server.ts` assembles a typed `ChromeState` in the root
loader (the chrome lives in root `Layout`, so its data loads there too):

```ts
interface ChromeState {
  banner:
    | { kind: "paused"; reason: string }
    | { kind: "halted" }
    | { kind: "degraded" }
    | null;
  liveStatusOk: boolean;      // false = live reads failed this request
  freshness: FreshnessMeta | null; // /api/v1/status meta; null = API unreachable
}
```

- **Live reads:** vault `get` + contract `epoch_status` over LCD, bounded
  timeout (reuse the boot-check transport). `paused → banner "paused"` with
  `pausedReason` and the §8.0 plain-language consequence line; `halted →
  "halted"` (halted outranks paused).
- **Degraded:** an open incident from `/api/v1/incidents` of the reconciler/
  indexer-lag kinds, OR `chain_height − indexed_height` from `/api/v1/status`
  beyond the lag threshold. Until M2.5/M3 report real heights and incidents,
  both inputs are honestly empty/null and no degraded banner shows; the logic
  is tested now via MSW-mocked envelopes.
- **Read failure is not health.** If the live reads fail, `liveStatusOk =
  false` and the footer shows "program status unavailable"; the banner slot
  never renders an implicit all-clear it cannot back (SECURITY.md: never lie
  about state). A failed API read only nulls `freshness` (footer "n/a"); it
  never fabricates a banner.

`ChromeState` is public chain data, not config: it crosses to the client as
loader data, and the §7 client-safe config allowlist is untouched.

### Components

Files under `apps/web/app/components/chrome/` (plus one shared component):

- `nav.tsx`: Learn (`/`) · Stake · Portfolio · Market · Validators ·
  Governance, locale-prefixed via `useLocale()`, `aria-current="page"` on the
  active route, keyboard operable, responsive collapse per the nuva/shadcn
  baseline.
- `env-badge.tsx`: renders `clientConfig.chainId`; quiet (muted) when
  `appEnv === "production"`, warning-tinted with an explicit label otherwise
  (§8.0). Uses the fixed status family, icon + label, never color alone.
- `banner.tsx`: the slot under the header, rendered only when
  `ChromeState.banner` is non-null. Severity mapping aligned with console
  §11.2 status semantics: paused → `--status-serious`, halted →
  `--status-critical`, degraded → `--status-warning`; every state ships icon +
  label + one plain-language consequence sentence (§11 register: explanation is
  first-class).
- `alerts-bell.tsx`: the anonymous placeholder only (§8.0: anonymous users see
  the feature advertised, not the bell). No wallet exists until M5, so this PR
  ships exactly the advert affordance; M6 replaces it.
- `freshness-footer.tsx`: chain id · "indexed to block N (Ns ago)" from
  `freshness` (null height or null meta renders "n/a", never a number) ·
  console link. Ages computed from `generated_at`.
- `app/components/verify-link.tsx`: `<VerifyLink target=... />` with a closed
  typed map per §12.2: `overview` (NAV/APR/TVV) | `epoch-ops` | `validators` |
  `redemptions` | `governance` → console view paths. Hrefs are always
  `${clientConfig.consoleUrl}/${path}`; quiet affordance styling (§11).
  Entity-level anchors stay a console follow-on (§14.13), not assumed here.

`root.tsx` `Layout` composes header (brand, `nav`, `env-badge`, `alerts-bell`,
`ThemeToggle`), `banner`, `main`, `freshness-footer`.

## 3. Security & invariants (enforced mechanisms with gating tests)

1. **Never lie about state** (SECURITY.md apps; §12.1). *Gate:*
   `test/chrome-state.test.ts` against the MSW harness: pristine fixtures → no
   banner; `paused: true` override → paused banner with reason; `halted: true`
   override → halted banner (and outranks paused); vault/LCD handler failure →
   `liveStatusOk: false` and no banner, plus the e2e assertion that the footer
   then shows "program status unavailable" rather than nothing.
2. **Freshness honesty** (§9.4/§12.1: null heights are "n/a", never fabricated).
   *Gate:* same suite: the real PR 1.2 status envelope (null heights) → footer
   renders "n/a"; a mocked enveloped status with heights → "indexed to block N";
   mocked lag beyond threshold or an open reconciler incident → degraded banner.
3. **Environment-locked verify links** (§12.2). The boot check is already
   gated (`test/boot-checks.test.ts`); this PR adds *gate:*
   `test/verify-link.test.ts`: every `VerifyTarget` in the closed union
   resolves to an href strictly prefixed by the booted `consoleUrl`, and the
   figure→view map is total (a target without a path is a type error, asserted
   with `satisfies`).
4. **`API_URL` stays server-only.** Classified in
   `scripts/server-only-env.json` in the same change; the standing
   `check:bundle`, `test/client-config.test.ts`, and `e2e/leaks.spec.ts` gates
   then fail CI if it ever reaches the bundle. No new client-safe config keys.
5. **Input bounding at the boundary** (SECURITY.md): `API_URL` zod-bounded
   (http/https URL) in `config.server.ts`; API responses parsed through the
   `@nvhash/api-types` envelope validators before use, LCD responses through
   the existing `@nvhash/chain-client` parsers; a shape failure degrades to the
   "unavailable"/null paths above, never a crash or a guess.
6. **Accessibility and i18n as standing gates:** new routes in the axe scan
   (both themes), all chrome strings in the `en` catalog
   (`test/i18n-coverage.test.ts`), status renderings icon + label on the fixed
   family (already enforced by `test/brand-tokens.test.ts`).

No PII anywhere in this PR: chrome state is public chain data plus the public
status endpoint; no addresses, sessions, or storage are introduced.

## 6. Open questions

- **Console view paths for the verify map:** §12.2 names the views (Overview,
  Epoch & Ops, Validators, Redemptions) but the console's route addressing is
  its own; confirm the concrete paths against `apps/console` at implementation
  time. Entity-level anchors remain the §14.13 console follow-on.
- **Footer "docs" link (§8.0 diagram):** no docs URL exists in config and user
  docs are not hosted yet. Proposal: omit the docs link from 4.1 and record it
  as a follow-on rather than adding a dead link or a speculative config key.
- **Degraded-lag threshold:** the §7 reconciler rows give cadence/tolerance for
  M2.5; the chrome needs one display threshold (blocks behind head) for the
  degraded banner. Proposal: a named constant in `chrome.server.ts` defaulting
  to the §7 `RECONCILE` cadence equivalent, revisited when M2.5 lands real
  heights; the 4.1 reviewer confirms the value.

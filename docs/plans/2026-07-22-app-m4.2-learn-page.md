## 1. Origin & problem statement

Master plan §2: *"Learn page (§8.1): hero + mechanism explainer with stepwise
honesty, live proof strip, yield decomposition, security/trust posture (audit
MDX content plane §5.4), incident history, exit explainer, CTA. Cold-start
renderings for every below-threshold metric."* Depends on 4.1 (merged chrome)
and **"3.1 contracts"**.

M3 has not started, so the 3.1 contracts do not exist. The master plan's M3
header prescribes the remedy: endpoint contracts (envelope + shapes) are
defined and mocked FIRST so the web lane builds without waiting for
implementations. Decision (Carlton, 2026-07-22): this plan carries that
contracts tranche itself rather than as a separate PR, accepting the small
`services/api` + `packages/api-types` surface inside a web-lane PR. PR 3.1
later implements real derivations against shapes this PR freezes.

What already exists:

- **Live plane (§5.1):** `@nvhash/chain-client` covers most of the §8.1 proof
  strip today: vault `get` (TVV, `total_shares`, so NAV is computable), `apr()`
  (nullable; `grossAprBps`/`netAprBps` plus the full rewards/commission/tips/
  AUM-fee decomposition and `windowSeconds`), `epochSnapshot()` (nullable;
  `eligibleCount`), `validators()`. All are MSW-mocked from the fixture corpus.
- **Indexed plane:** only `/api/v1/status` and `/api/v1/incidents` exist, and
  incidents rows have no frozen shape. Participant count, program age, epoch
  history (the step chart), and the incident feed all need 3.1 contracts.
- **Chrome (4.1):** the page renders inside the shipped chrome; `VerifyLink`
  (closed map) and the freshness/degradation machinery are done.

## 2. Mechanism

### Tranche 1: 3.1 endpoint contracts (shapes frozen, honestly empty)

Only what Learn consumes is frozen here; `/validators` stays with PR 4.3.

- `packages/api-types` (types only, zero runtime deps, matching the package's
  charter): `ProgramMetrics { participant_count: number | null;
  program_started_at: string | null; epoch_count: number | null }`;
  `EpochRow { epoch_index: number; ended_at: string; nav: string;
  tvv: string; net_apr_bps: number | null }`; `IncidentRow { kind:
  IncidentKind; severity: "info" | "warning" | "critical"; opened_at: string;
  closed_at: string | null; height: number | null }` with `IncidentKind` as
  the closed union mirroring the indexer's Prisma enum (contract_halted,
  vault_paused, slash_write_down, redemption_refund, jail_report,
  epoch_overdue, reconciler_divergence, indexer_lag).
- `services/api`: `GET /api/v1/metrics` (enveloped `ProgramMetrics`, all-null
  scaffold data) and `GET /api/v1/epochs` (enveloped `EpochRow[]`, empty,
  bounded by the existing `paginationSchema`). `/api/v1/incidents` keeps its
  route and adopts `IncidentRow[]` as its declared type (still `[]` until
  3.1). Scaffold responses stay honest: null heights, empty data, exactly the
  PR 1.2 posture.
- `services/api/test/envelope-contract.test.ts` extended: the two new routes
  are enveloped, null-height, shape-exact; pagination bounds rejected outside
  1..200 / 0..1,000,000.
- `apps/web/app/mocks/handlers.ts`: MSW handlers for `/metrics` and `/epochs`
  built with the `@nvhash/api-types` `envelope()` producer (scaffold shape);
  tests overlay populated variants with `server.use()`.

### Tranche 2: Learn data assembly (server)

- `apps/web/app/api/api.server.ts`: extract the bounded `fetchApiJson` +
  freshness-meta zod schema from `chrome.server.ts` into one shared module
  (chrome imports move; no behavior change). Add zod row schemas for
  `ProgramMetrics`, `EpochRow[]`, `IncidentRow[]` pinned to the api-types
  shapes with `satisfies z.ZodType<...>`.
- `apps/web/app/learn/learn.server.ts`: `loadLearnData(config)` runs all
  reads concurrently with the chrome's discipline (each read parses or
  degrades to null; never throws): vault `get`, `apr()`, `epochSnapshot()`
  over LCD; `/metrics`, `/epochs?limit=48`, `/incidents` over `API_URL`.
  Returns a typed `LearnData` with per-figure nullability; every indexed
  figure carries its envelope meta so the UI can label staleness (§12.1).
- `apps/web/app/learn/amounts.ts`: pure BigInt-safe display helpers: NAV =
  `totalVaultValue / total_shares` at the §7 exponent-9/15 scales, HASH
  amounts, bps to percent. Golden-value unit tests against the fixture
  corpus numbers (never float math on amounts).

### Tranche 3: the page

`routes/home.tsx` becomes the real Learn page (loader + sections), replacing
the scaffold note. Components under `apps/web/app/components/learn/`:

- `hero.tsx`: plain-language mechanism explainer with the §8.1 stepwise
  honesty sentence, and a static inline-SVG flow diagram (deposit → pool →
  validators → rewards → NAV step) with a CSS highlight sequence gated by
  `prefers-reduced-motion: no-preference` (§11 motion rules; 150-200 ms
  ease-out).
- `proof-strip.tsx`: NAV, net APR (gross in the caption, window-labeled,
  minimum-window rule below), TVL, participant count, program age, eligible
  validators. Live figures render live; indexed figures render "n/a" until
  heights are real; every tile gets `<VerifyLink target="overview" />`.
- `nav-step-chart.tsx`: step-after NAV series from `EpochRow[]` (repo dataviz
  method: `--viz-cat-1`, single series titled not legended, no interpolation
  ever) with a table-view toggle. Below two rows: the cold-start explainer
  rendering instead of an empty chart.
- `yield-sources.tsx`: the `Apr {}` decomposition in lay language (rewards +
  commission + tips, minus AUM fee) with the §8.1 honesty note that
  validators fund commission/TIP themselves; qualitative compare-to-self-
  staking panel (no fabricated baseline number; open question 4).
- `trust-posture.tsx`: renders `apps/web/app/content/trust.ts`, a typed
  build-reviewed content module (§5.4 amended per open question 2). Pre-audit
  reality renders honestly: audit `null` shows the SECURITY.md posture
  (pre-audit, third-party audit mandatory before mainnet), multisig paragraph,
  plain-words risk register. No marketing adjectives.
- `incident-history.tsx`: the `IncidentRow[]` feed with severity icon + label
  on the fixed status family, and the §8.1 proud empty state ("generated from
  chain history, not curated").
- `exit-explainer.tsx`: the two §8.4-framed paths side by side; the DEX
  column states honestly that no bridged nvHASH DEX exists in v1 (§13),
  native redemption states the 60-day ceiling as the only promise.
- `cta.tsx`: links to `/stake` (the honest stub until M5). Funnel counters
  are explicitly NOT in this PR (PR 7.6, blocked on §14.10).

All copy goes through the `en` catalog (i18n coverage gate).

## 3. Security & invariants (enforced mechanisms with gating tests)

1. **Never lie about state** (SECURITY.md apps; §12.1). *Gate:*
   `apps/web/test/learn-data.test.ts` against the MSW harness: pristine
   fixtures → live figures populated, indexed figures null; LCD handler
   failure → the affected live figures are null and the page still renders
   (no crash, no stale substitute); API failure or off-shape payload → the
   indexed figures degrade to null, never a guess. e2e asserts the "n/a"
   renderings appear where figures are null.
2. **Freshness labels are structural** (§9.4/§12.1). *Gate:* same suite:
   every indexed figure in `LearnData` carries envelope meta; null heights
   render "n/a"; a populated mocked envelope renders the figure with its
   window/height label.
3. **Input bounding at the boundary** (SECURITY.md). *Gates:* the services/api
   contract tests bound the new routes' query params via `paginationSchema`;
   the web tier parses every API response through the zod row schemas and
   every LCD response through `@nvhash/chain-client` parsers; `amounts.ts` is
   BigInt-only (a float in the amount path is a review-rejectable defect,
   asserted by golden-value tests).
4. **Verify links stay environment-locked** (§12.2): only existing closed-map
   targets are used; no new targets, no raw console URLs. *Gate:* the standing
   `test/verify-link.test.ts` plus an e2e assertion that every proof-strip
   verify href is prefixed by the booted console origin.
5. **Accessibility, i18n, palette as standing gates:** route `/` is already in
   the axe scan (both themes; the chart must pass it, and ships a table
   alternative); all new copy in the `en` catalog; chart colors from the
   validated `--viz-*` tokens (standing `check:palette` and
   `test/brand-tokens.test.ts`).
6. **No PII, no analytics** in this PR: aggregate funnel counters remain PR
   7.6 behind the §14.10 decision; nothing here keys anything by address.

## 6. Open questions

1. **`/metrics` field set and derivability:** `participant_count` (distinct
   depositor addresses), `program_started_at` (first indexed activity), and
   `epoch_count` must be derivable from the `indexed` schema PR 2.1/2.2
   populate. Frozen here as nullable; the 3.1 implementer confirms
   derivability before implementing, and any change is a spec-level shape
   amendment.
2. **§5.4 content plane:** the spec says MDX; there is no audit report yet
   and zero MDX infrastructure. Proposal: a typed `content/trust.ts` module
   now (build-reviewed by PR exactly as §5.4 intends), MDX tooling when the
   first real report lands. Amends §5.4 with a dated revision note.
3. **APR minimum-window rule:** propose rendering net APR only when `apr()`
   is non-null AND `epochIndex >= 2` (at least two settled epochs), otherwise
   "n/a (insufficient history)" with the window always labeled. Named
   constant `MIN_APR_EPOCHS` in `learn.server.ts`; the 4.2 reviewer confirms.
4. **Compare-to-self-staking panel:** a numeric self-staking baseline is not
   derivable from a single live read (validator commissions vary). Proposal:
   ship the qualitative comparison plus the vault's own gross-vs-net
   decomposition, and record a follow-on to source a real baseline (possibly
   x/mint inflation + median commission via 3.1) rather than fabricating one.
5. **Hero animation:** proposal above ships a static SVG with a CSS highlight
   sequence honoring `prefers-reduced-motion`; the fuller §8.1 animated
   pipeline can follow as polish without blocking 4.2.

## 1. Origin & problem statement

Master plan §2: *"Market page + program history views (§8.5): NAV-vs-market
step/line pair, premium/discount explainer, depth, supply location; epoch
trend views from `epoch_snapshots`."* Depends on 4.1 and "3.1/3.2 contracts",
BOTH now delivered for real on main:

- **`GET /api/v1/market` (PR 3.2)** is shape-complete and honest-empty:
  `MarketSummary { sample: MarketSample | null; bridged_supply:
  BridgedSupplyRow[] }`, with venue + pool + `sampled_at` riding IN the
  payload, signed truncated `premium_discount_bps` computed against the NAV
  current at the sample's time (null before any settled epoch), `price` as
  nhash per whole nvHASH, and `depth_bands`. With the PR 2.4 sampler parked
  (§14.3) and no bridged nvHASH in v1 (§13 decision 4), `sample` is null and
  `bridged_supply` empty in production; populated states are exercised via
  MSW-mocked envelopes, exactly the 4.1 degraded-banner pattern.
- **`GET /api/v1/epochs` (PR 3.1)** serves real per-settlement rows
  (`epoch_index`, `ended_at`, nullable `nav`, `tvv`, nullable
  `net_apr_bps`), the series behind the §8.5 history views.
- **Supply location:** PR 3.2's recorded §8.5 amendment: the API provides
  the BRIDGED side only; LOCAL supply is a live chain read owned by the web
  tier (vault `get` `total_shares`), composed on the page.

Two honesty rules dominate this page (§12.1): market data has no
chain-canonical plane, so venue + sample time label every market figure and
**market figures never carry a verify link** (§12.1 rule 4); and the v1
shell is a labeled forthcoming surface, never a fabricated market.

## 2. Mechanism

### Tranche 1: shared step-chart extraction

Third chart instance incoming; extract
`apps/web/app/components/charts/step-chart.tsx` from 4.2's
`nav-step-chart.tsx`: props `{ locale, title, caption, series:
Array<{ label: string; x: string; value: number; display: string }>,
tableColumns }`, step-after geometry (flat-series centering fix carried
over), single `--viz-cat-1` series, table-view toggle, axis min/max labels.
`nav-step-chart.tsx` becomes a thin adapter over it (behavior identical; the
existing Learn e2e assertions are the regression gate).

### Tranche 2: market data assembly (server)

- `apps/web/app/api/api.server.ts`: zod schemas pinned with `satisfies` to
  the 3.2 shapes: `marketDepthBandSchema`, `marketSampleSchema` (price and
  amounts as decimal strings, `premium_discount_bps` bounded signed int,
  nullable), `bridgedSupplyRowSchema`, `marketSummarySchema`, and
  `marketEnvelopeSchema = envelopeSchema(marketSummarySchema)`.
- `apps/web/app/market/types.ts` (client-safe): `MarketData { summary:
  Envelope<MarketSummary> | null; localSupply: string | null; epochs:
  Envelope<EpochRow[]> | null }` with display strings prepared server-side
  (BigInt never crosses).
- `apps/web/app/market/market.server.ts`: `loadMarketData(config)` with the
  established per-figure discipline: `/api/v1/market` (parse or null),
  `/api/v1/epochs?limit=48` (parse or null; same request the Learn page
  makes), vault `get` for local supply (`vault.totalShares` formatted
  compact via the 4.2 amount helpers; read failure nulls only this figure).
  Premium/price/depth are RENDERED from the sample verbatim; the web tier
  never recomputes market math (§9.5(4) lives in the API).

### Tranche 3: the page

`routes/market.tsx` becomes the real page (loader + sections), replacing the
4.1 stub. Components under `apps/web/app/components/market/`:

- `market-status.tsx`: the §13-decision-4 shell, driven by the contract:
  `sample === null` renders the labeled forthcoming state (one calm
  sentence: no bridged nvHASH market exists yet; this page activates with
  the bridge). A non-null sample renders price + premium/discount with the
  mandatory `venue · sampled N ago` label line; a null
  `premium_discount_bps` inside a sample renders "n/a", never 0. NO verify
  link anywhere in this component (§12.1 rule 4), asserted by test.
- `premium-explainer.tsx`: static consumer copy for why a spread exists
  (stepwise NAV creates a pre-/post-settlement seam, liquidity, bridge
  transit costs). Renders in both shell and active states: the explainer is
  the education, not the data.
- `depth.tsx`: `depth_bands` as a small table (side, slippage bps, size in
  nvHASH), rendered only when a sample exists; carries the same venue +
  sample-time label.
- `supply-location.tsx`: local supply (live, real today: total nvHASH
  shares, compact) beside bridged rows (empty state: "all nvHASH lives on
  Provenance today"), each bridged row labeled with its chain + sample
  time.
- `history.tsx`: the program history views from `/epochs` via the shared
  step chart: NAV per settlement (null-NAV epochs filtered exactly as
  Learn's chart does) and TVV per settlement (compact HASH), each with
  table view; net APR per settlement as a third series when non-null rows
  exist. This section is real data on day one. NAV/TVV tiles keep the
  `overview` verify link (chain-derived figures may verify; market figures
  may not).
- Copy through the `en` catalog, monthly-settlement vocabulary; alert hooks
  for spread thresholds are M6 (deferred, noted in §5).

## 3. Security & invariants (enforced mechanisms with gating tests)

1. **Never fabricate a market** (§12.1, §13 decision 4). *Gate:*
   `apps/web/test/market-data.test.ts` (MSW): pristine (real honest-empty
   contract) → `sample` null, page state "forthcoming" (e2e asserts the
   labeled shell); populated mocked envelope → price/premium/depth render
   with venue and time; `premium_discount_bps: null` inside a sample →
   "n/a", never a number; off-shape or over-bound payloads → `summary`
   null, distinct unavailable state.
2. **Venue + sample-time labeling is structural** (§8.5/§12.1). *Gate:* the
   populated e2e/unit cases assert every rendered market figure's label
   line; the component renders figures only through a labeled wrapper.
3. **No verify links on market figures** (§12.1 rule 4). *Gate:* e2e asserts
   zero verify-link anchors inside the market-status/depth sections while
   the history section keeps its `overview` link.
4. **Input bounding at the boundary:** all API responses through the pinned
   zod schemas (arrays bounded, bps bounded signed, decimal strings
   regex-checked); LCD through chain-client parsers; BigInt-only display
   math via the existing golden-gated helpers.
5. **Standing gates:** `/market` is already in the axe route list (both
   themes scan the real page); i18n coverage for all new copy; palette and
   brand-token validation for the chart usages; `check:bundle` unchanged
   (no new config).
6. **No PII, no analytics;** spread-threshold alert rules are M6 machinery.

## 6. Open questions

1. **NAV-vs-market pair pre-bridge:** the §8.5 two-series chart cannot render
   a market line until samples exist. Proposal: the history section renders
   the NAV step series alone with the market line named in the caption as
   forthcoming; the pairing activates by data presence, no code change.
   Reviewer confirms.
2. **Local supply source:** proposal reads vault `get` `total_shares` live
   (one call, fixture-covered, canonical). Alternative (indexed TVV row)
   is staler for a live figure; rejected under §5.1.
3. **APR history series:** `net_apr_bps` is nullable per row. Proposal: the
   APR chart renders only rows with non-null bps and states the omission in
   its caption; below two plottable rows it shows the standard cold state.
4. **Step-chart extraction depth:** proposal keeps the shared component
   presentation-only (series in, SVG + table out) and leaves data mapping in
   each caller; resist a charting-framework temptation (dataviz method +
   YAGNI).

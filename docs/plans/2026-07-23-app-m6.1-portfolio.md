Two constraints shape the whole design:

1. **The [R2] balance honesty problem (3.3 delivery note, §9.4).** Indexed
   `transactions` cannot see bank transfers (`transfer_in`/`transfer_out`
   exist in the enum with no producing worker), which is why 3.3 refused to
   serve a balance. The same limitation hits cost basis, effective yield,
   and the accrual series. This plan's answer: compute over swap/redemption
   events only, serve an explicit history-state flag, cross-check against
   the live balance in the web tier, and label rather than hide divergence
   (§2.7).
2. **ADR-001 plane split.** Everything derived from indexed data belongs to
   `services/api`; the web tier owns live reads and composes headline
   figures from both planes with §12.1 labeling.

## 2. Mechanism

### 2.1 The fold (pure derived-metrics core, `services/api`)

One pure function, new module `services/api/src/portfolio-metrics.ts`:

```ts
derivePortfolioMetrics(
  txsAsc: TransactionFact[],     // full history, (height, msgIndex) asc
  epochsAsc: EpochFact[],        // all epoch_snapshots, epochIndex asc
): PortfolioMetrics
```

BigInt-only, scale-then-floor, loud `toSafeInt` guards (the `derive.ts`
conventions). Internal state: two pools plus realized gain.

| Event | Effect |
| --- | --- |
| `swap_in` | `heldShares += shares; heldBasisNhash += nhash` |
| `swap_out_request` | `moved = floor(heldBasisNhash × shares / heldShares)`; move `shares`/`moved` from held pool to escrow pool |
| `redemption_payout` | `removed = floor(escrowBasisNhash × shares / escrowShares)`; shrink escrow pool; `realizedGainNhash += nhash − removed` |
| `redemption_refund` | `returned = floor(escrowBasisNhash × shares / escrowShares)`; move `shares`/`returned` from escrow pool back to held pool |
| `transfer_in` / `transfer_out` | no pool change; `excludedTransfers++` |

Average-cost per §14.11: remaining basis is the held pool's
`heldBasisNhash`; proportional floor moves keep the pool-sum identity exact
(no per-share rounding drift). Refunds realize nothing (shares and basis
return; contract §8's failure mode is a refund, not a sale).

**Inconsistent history is an error state, not a lie:** a payout/refund
against an empty escrow pool, or shares going negative, sets
`history_state: "inconsistent"` and nulls the derived fields (the fold
never throws mid-response). Closed union:
`history_state: "complete" | "has_transfers" | "inconsistent"`
(`has_transfers` when `excludedTransfers > 0`).

### 2.2 Effective yield (§9.5.2, pinned)

Yield-bearing shares = `heldShares + escrowShares` (escrowed shares
re-price at payout NAV, contract §8, so they participate in NAV steps until
the payout event).

Per epoch step `e` (with predecessor `p`, both having non-null NAV):

```
value_at(shares, E)   = floor(shares × E.tvvAfter / E.totalShares)      // nhash
gain_e                = value_at(S_e, e) − value_at(S_e, p)             // S_e = yield-bearing shares at step e
dur_e                 = e.endedAtSeconds − p.endedAtSeconds
personal_apr_bps_e    = floor(gain_e × 10_000 × SECONDS_PER_YEAR / (value_at(S_e, p) × dur_e))
SECONDS_PER_YEAR      = 31_536_000                                       // 365 d, matches program APR convention
```

`personal_apr_bps_e` is `null` when `S_e = 0`, either NAV is null (empty
vault epoch), `p` predates the first deposit, or `dur_e ≤ 0`. Serialized
beside the program's `net_apr_bps` for the same epoch so the panel renders
the two-line "am I getting what the headline says?" comparison without
re-deriving anything client-side.

Overall figure since first deposit: `gain_total = Σ gain_e`;
`TWAB = Σ value_at(S_i, current NAV basis at interval i) × dt_i / W` over
the position's sub-intervals (boundaries at every event and epoch step);
`effective_apr_bps = floor(gain_total × 10_000 × SECONDS_PER_YEAR / (TWAB × W))`.
Cold-start per §14.12: `null` until ≥ 1 completed epoch step after the
first deposit, and the UI renders "first epoch not yet settled", never a
zero.

### 2.3 Accrual series + markers (§8.2 accrual tracker)

Step-after series of position value: one point at every epoch step and
every event (balance changes at events, NAV changes at steps; both are
steps, nothing interpolated, §13):
`{ time, height, value_nhash }` with
`value_nhash = value_at(yield-bearing shares, NAV basis current then)`.
Markers: `{ time, txhash, kind, shares, nhash }` per event. Markers are
capped at the most recent `200` with an explicit `markers_truncated: true`
flag (no silent caps); the series itself is bounded by epoch count
(calendar-month epochs) plus event count within the marker cap window.

### 2.4 New endpoint: `GET /api/v1/portfolio/metrics?address=`

`defineEnveloped` route, `auth: "address"`, `querySchema:
portfolioQuerySchema` (reused), source `"indexed"`. Shape frozen in
`packages/api-types/src/rows.ts`:

```ts
interface EffectiveYieldPoint {
  epoch_index: number;
  ended_at: string;                    // ISO-8601
  personal_apr_bps: number | null;
  net_apr_bps: number | null;          // program figure for the same epoch
}
interface AccrualPoint { time: string; height: number; value_nhash: string; }
interface AccrualMarker {
  time: string; txhash: string; kind: TransactionKind;
  shares: string; nhash: string;
}
interface PortfolioMetrics {
  address: string;
  history_state: "complete" | "has_transfers" | "inconsistent";
  indexed_share_balance: string;        // held pool (excludes escrow)
  escrowed_share_balance: string;
  cost_basis_nhash: string | null;      // held-pool average-cost basis
  escrowed_basis_nhash: string | null;
  realized_gain_nhash: string | null;   // signed decimal string
  effective_apr_bps: number | null;     // since first deposit; §14.12-gated
  yield_by_epoch: EffectiveYieldPoint[];
  accrual: AccrualPoint[];
  accrual_markers: AccrualMarker[];
  markers_truncated: boolean;
}
```

Reader additions (`src/reader.ts` + `reader-prisma.ts` + the test fake):
`transactionsAscFor(address)` (full history, internally chunked reads of
1 000 rows so no single query is unbounded) and `listEpochsAsc()` (all
snapshots ascending; bounded by monthly cadence). Derived fields stay
compute-on-read: **no new `indexed` columns** (the schema allowlist gate
stays untouched).

### 2.5 CSV completeness amendment (consumes §14.11)

3.3's `?format=csv` branch currently applies the JSON pagination bounds
(default 50, max 200), which silently truncates the "statement of fact."
Commit B amends: `format=csv` ignores `limit`/`offset` and streams the
**complete** indexed history via `transactionsAscFor` (columns, guard, and
`X-*` freshness headers unchanged). Recorded as a §9.4 revision in the same
change; gated by a test exporting more rows than the JSON max.

### 2.6 Web composition (live plane + indexed plane, labeled)

`app/portfolio/portfolio.server.ts` `loadPortfolioData(config, session)`,
never throws, every read degrades to `null` independently (the
`market.server.ts` pattern):

- **Live:** `VaultClient` vault record (share denom, `tvv`,
  `totalShares`) and `BankClient.balance(address, shareDenom)`.
- **Indexed (assertion-scoped):** `/portfolio` (summary + active
  redemptions), `/portfolio/metrics`, `/transactions?limit=50&offset=N`
  (history page N from a zod-bounded `?page=` search param).
- **Composed headline figures** (shared BigInt helpers, floor):
  current value = `floor((liveBalance + escrowedShares) × tvv / totalShares)`;
  accrued gain = current value − (held basis + escrow basis) + realized
  gain. Both labeled live-plane; when the live read fails they fall back to
  the indexed-plane figures with the stale-source label (§12.1), never a
  blank.

### 2.7 Divergence honesty

When `liveBalance ≠ indexed_share_balance` or
`history_state ≠ "complete"`, every basis-derived figure (cost basis,
accrued gain, effective yield, accrual chart) renders with an explicit
"history incomplete: this address has activity the program's indexer does
not track (transfers)" state and the §14.11 "aid, not a tax position"
label. The balance and current value (live plane) are unaffected. Nothing
is silently reconciled.

### 2.8 R3 harness (master plan §4; the property layer this PR introduces)

1. **Trace export (commit A, contracts):** `bin/simulate.rs` gains
   `--trace-out <dir>` (with the existing seed control); `sim.rs` records,
   per scenario: `epochs: [{ index, ended_at_seconds, tvv_after,
   total_shares }]` and per-address `events: [{ address, kind, shares,
   nhash, seq }]` for deposit / redeem-request / payout / refund, JSON
   mirroring `TransactionRow`/`EpochRow` field names so the TS harness
   replays through the production mappers. A small set of seed-pinned
   traces is committed to `packages/fixtures/fixtures/sim-traces/` with a
   manifest recording the seeds and generator command
   (seed-reproducible per `SECURITY.md`).
2. **Property tests (commit B, `services/api`, adds `fast-check` following
   the indexer's replay-test shape):** random event plans +
   the committed traces both assert:
   - **Value conservation:** for every history prefix,
     `(pool value at current NAV) − (held+escrow basis) + realized gain =
     Σ gain_e ± dust`, dust bounded by one base unit per floor site
     (≤ events + epochs).
   - **Hold-only equivalence:** a single deposit before the first step and
     no further activity yields `personal_apr_bps_e` equal to the
     NAV-step-derived program APR for every epoch (within 1 bps flooring).
   - **Basis sanity:** bases are never negative; an emptied pool has zero
     basis; escrowed shares equal the active-redemption escrow that
     `derivePortfolio` (3.3) reports for the same history.
   - **Refunds realize nothing;** payout realized gain equals
     `nhash − proportional escrow basis` exactly.
   - **Purity/prefix determinism:** the fold is a pure function of its
     input ordering (replay stability, the indexer idempotency culture).

## 4. Security & invariants (enforced mechanisms with gating tests)

1. **Cross-address rejection extends to the new endpoint.**
   `/portfolio/metrics` joins `PERSONAL_PATHS`; A-requesting-B → 403,
   absent/invalid → 401, `internal:notifier` → 403. *Gate:* the standing
   `test/cross-address.test.ts` matrix (registry-driven pipeline order
   unchanged).
2. **Session scope on every personal web surface.** The page loader uses
   `getSessionContext` (anonymous → prompt-and-explain); the CSV proxy
   uses `requireSession` (anonymous → 401); the acting address is never a
   query param. *Gates:* `test/session-scope.test.ts` (new route case),
   `test/session.test.ts` unchanged.
3. **All inputs validated and bounded at entry.** `?address=` bech32
   (existing schema); web `?page=` zod-bounded; reader chunk size fixed;
   no unbounded single query. *Gates:* the registry-driven query-bounds
   harness (auto-covers the new route); `test/portfolio-data.test.ts`
   page-param bounds case.
4. **BigInt-only, scale-then-floor, loud overflow guards** across fold and
   composition; floats never touch amounts. *Gates:* unit goldens, the R3
   property + trace suites (§2.8), the integration reader round-trip.
5. **Never lie about state.** `history_state` closed union; divergence and
   §14.11 aid labeling; §14.12 cold-start ("first epoch not yet settled",
   never zero); marker truncation flagged; live-plane vs indexed-plane
   source labels; no interpolation anywhere (step-after only). *Gates:*
   `test/portfolio-data.test.ts` honesty matrix, API populated/empty
   contract cases, e2e cold-state assertions.
6. **Simulation coverage across the input domain (R3).** The derived math
   is property-tested against randomized plans and the contract sim's
   seed-reproducible traces, including negative-ΔNAV (slash) scenarios.
   *Gates:* §2.8 suites, standing in `services/api` CI from commit B.
7. **No new persisted data; no PII.** Compute-on-read only: the `indexed`
   schema allowlist test is untouched; the web tier stores nothing new;
   the CSV proxy adds no logging that links addresses to IPs. *Gates:*
   `schema-allowlist.test.ts` (unchanged = passing), the existing
   log-scrubbing gate.
8. **CSV remains injection-guarded and now complete.** `csvField` guard
   and pinned columns unchanged; full-history behavior tested past the
   JSON pagination max. *Gate:* the commit B CSV test.
9. **Client bundle stays secret-free.** `EXPLORER_URL` is an explicit
   client-safe allowlist amendment; `API_SERVICE_ASSERTION_KEY` remains
   server-only. *Gate:* `check:bundle` with the new var classified.
10. **Standing gates continue on every commit:** axe (both themes; the
    now-real `/portfolio`), i18n coverage for all new copy,
    `check:palette` on any token change, envelope/read-only/rate-limit
    harnesses.

   (`markers`/`compare` optional props, back-compat, one chart system);
   confirm at review if the diff turns out invasive.
6. **Windowing.** v1 serves per-epoch series + since-first-deposit

   reduces to these two). Confirm.
7. **Accrual marker cap.** 200 + `markers_truncated` flag (§2.3);
   confirm the number.

## 2. Mechanism

### 2.1 The three drills, and which assumption each can falsify

The §4b drill rule says drills exist to contradict assumptions. Each scenario
below names the assumption it tests and what today's code says will happen.

**Drill 1 — corrupt an indexed row.** `UPDATE indexed.epoch_snapshots SET
total_shares = total_shares + 1 WHERE epoch_index = <chain's latest>` via
`docker compose exec postgres psql` (the driver, §2.6 — the chain's *latest*
epoch, because the reconciler compares only that row, `deltas.ts:39-59`; a
historical row would trip nothing, and the epoch-history worker will not heal
the corruption because its cursor is already past the crank height). Within
≤ 2 reconciler cadences (`RECONCILE_INTERVAL_MS`, default 30 s) a
`reconciler_divergence` incident opens (`incidents.ts:119-126`), the chrome's
`isDegraded` flips on the open incident (`chrome.server.ts:41`, `:54-59`), and
the banner renders "Data degraded / Recent history may lag the chain. Live
figures remain authoritative." The drill asserts the banner, the live plane
still rendering, the coming-soon shells still labeled (CO-23), then repairs
the row and asserts the banner clears (both directions, like the acceptance
test). *Assumption tested:* the alarm chain is wired end-to-end through real
processes — reconciler loop → `incidents` table → `/api/v1/incidents` →
chrome. Expected to pass against today's build; it is the one scenario whose
unit-level precursor (CO-13) already exists.

**Drill 2 — kill the indexer** (`docker compose stop indexer`). *Assumption
tested:* "canonical values survive, history dims." Live values survive
(nothing in the web tier touches the indexer). But **history does not dim on
today's build — this drill fails, correctly**: see §2.2.

**Drill 3 — kill the LCD** (`docker stop dev-node`). *Assumption tested:*
"indexed values carry stale labels" and no fabricated program health. The
chrome's live-read failure path is honest (`chrome.server.ts:88-97`: no
banner, footer "Program status unavailable"; every live figure "n/a", never 0)
— that half passes and is already offline-covered. But the *stale label* half
fails for the §2.2 reason, and the drill also exposes §2.3: the reconciler's
live read throws, `runReconciler` has no per-pass catch
(`reconciler/index.ts:73-79`), the rejection hits
`onLoopCrash("reconciler")` (`src/index.ts:157`), which aborts **every**
worker and exits the process (`:131-140`) — and compose defines **no restart
policy for any service** (no `restart:` key exists in
`infra/dev/compose.yaml`), despite `src/index.ts:20-22` explicitly claiming
"compose restarts the process from the last committed cursor". One LCD blip
permanently kills ingestion *and the alarm that is supposed to outlive it*.

### 2.2 The data-age gap: `generated_at` is not the data's age

The freshness envelope's heights come from the latest `reconciler_runs` row
(`services/api/src/derive.ts:142-157`, `reader-prisma.ts:438-440`), but its
only timestamp is `generated_at` — "the response was generated (server
clock)" (`packages/api-types/src/envelope.ts:39`) — and the footer's "(`{age}`
ago)" is computed **from `generated_at`**
(`apps/web/app/chrome/freshness.ts:14-18`). With the indexer process dead the
API keeps serving: frozen heights, a `generated_at` of *now*, and a footer
reading "Indexed to block H (0s ago)". The degraded computation
(`chrome.server.ts:48-53`) compares `chain_height − indexed_height` — both
frozen together, so the lag never grows and the banner never flips. A dead
indexer is rendered indistinguishable from a healthy one. That is precisely
the "never lie about state" violation the drills exist to catch, found at plan
time by asking what the drill would observe.

**Mechanism (commit B): expose the data's age and consume it.**

- `services/api`: `IndexedReader.heads()` additionally returns the run's
  `ranAt`; `/api/v1/status`'s data payload gains
  `reconciled_at: string | null` (ISO-8601, null when no run exists —
  `FreshnessMeta` itself is untouched, because it is universal and this fact
  belongs to the status descriptor the chrome already parses,
  `routes.ts:185-206`).
- `apps/web`: `isDegraded` gains a third clause — heads present but
  `now − reconciled_at > DEGRADED_STALE_SECONDS` → degraded. The constant is
  in-code beside `DEGRADED_LAG_BLOCKS` (`chrome.server.ts:34`), **not
  env-tunable** (the tolerances rule, `tolerances.ts:1-5`): proposed 300 s
  = 10× the reconciler cadence, so one slow pass never flips it. The footer's
  age switches to `reconciled_at ?? generated_at`, so "(5m ago)" describes the
  data, not the HTTP response.
- `reconciled_at: null` with non-null heads cannot occur (both derive from the
  same row); null heads + null `reconciled_at` is cold start, which is a
  distinct rendered state and deliberately **not** degraded
  (`lag.ts:38-47`) — the clause preserves that.

Drill 2 then has something true to observe: stop the indexer, wait past the
threshold, the banner flips and the footer age grows. "History dims" becomes
a mechanism with two gates (the generated chrome matrix, §4b C4, and the
drill itself) instead of a sentence in a plan.

### 2.3 The reconciler must survive a transient chain outage; the process must survive the reconciler

Two changes, both forced by drill 3:

- **Per-pass tolerance (commit A).** `runReconciler`'s loop catches a failed
  `reconcileOnce`, logs it, and sleeps to the next cadence. The reconciler has
  no cursor to drift (it "advances no cursor", `reconciler/index.ts:6-7`), so
  the workers' deliberate crash-fatal rule (`src/index.ts:20-22`) does not
  apply to it: a skipped pass is honest (the previous run's `ranAt` ages, and
  §2.2 now surfaces exactly that), while a killed process is a silenced alarm.
  A pass is all-or-nothing — if any live read fails, nothing is derived and
  nothing is closed that pass (a failed vault read must never read as
  "unpaused", §2.4).
- **Restart policy (commit C).** `indexer`, `api`, and `web` gain
  `restart: unless-stopped` in `infra/dev/compose.yaml`, making
  `src/index.ts:20-22`'s stated contract true. Worker crashes stay fatal and
  now actually resume from the committed cursor; the drill driver's recovery
  phase asserts the stack returns to healthy after the LCD comes back.

### 2.4 `vault_paused` lands (D30), and what the decoder actually is

The chrome's paused banner is a **live** read — `vault.getVault()` →
`vault.paused` / `pausedReason` (`chrome.server.ts:86-88`,
`packages/chain-client/src/vault.ts:185-187`: `GET vault/v1/vaults/{id}`).
The deferred incident kind is the **indexed-plane durable record** of the same
fact (app-spec §9.6: "vault paused/unpaused (with reason)"), and every
consumer of it already exists and is waiting: the wire union carries it
(`packages/api-types/src/rows.ts:19`), the Learn incident history has its copy
key (`app/components/learn/incident-history.tsx:20`), and the notifier already
maps `vault_paused → vault_status` (`app/lib/services/alerts.server.ts:171`).
Only the producer is missing.

The producer (commit A): `ReconcilerDeps` gains `vaultAddress` (already in the
indexer config — compose passes `VAULT_ADDRESS`, fail-closed when blank);
`readLive` adds one pinned read,
`pinned.getAtHeight(`vault/v1/vaults/${vaultAddress}`, {}, head)`
(`transport/rpc.ts:268-277`), with a **local** parse of
`{vault: {paused, paused_reason}}` — the mirror discipline, not a chain-client
import (indexer-design-notes "Local mirrors over cross-package imports").
`LivePlane` gains `pause: { paused: boolean; reason: string }` (never null —
§2.3's all-or-nothing pass rule covers the failure case). Derivation is the
`contract_halted` shape (`incidents.ts:149-159`): closeable, dedupeKey
`"paused"`, payload `{reason}`, proposed severity `warning` (halted stays
`critical`; §7 Q2 confirms against console §11.2 alongside CO-24). The
`IncidentKind` union in `incidents.ts:23-28` extends; the Prisma enum already
holds all eight kinds (`prisma/incidents.prisma:23-34`) — no migration, no
allowlist change.

The pause **drill** (lane, not per-PR): pause the vault, observe *both* planes
— the live banner (paused outranks degraded, pinned at
`test/chrome-state.test.ts`) *and* the incident opening; unpause, observe
close. On the governed devnet the contract's `pause_vault`/`unpause_vault`
admin variants (`app/tx/build.ts:189-196`) are behind the group policy, so the
drill drives the fast ops policy (40 s voting period,
`infra/devnet/bootstrap/nvhash-group-bootstrap.sh:47-55`) with the drill keys
— propose, two votes, exec, ≈60–90 s. [VERIFY: whether the vault module also
exposes a direct admin-level pause tx (`provenanced tx vault pause`, a
`paused_reason` argument) usable by the vault's admin key on devnet; if so the
drill uses it and the governance path stays a separate lane case.]

### 2.5 `jail_report` and `epoch_overdue`: the cheapness question, answered with evidence

**`jail_report` is cheap — recommend landing it in commit A** (D30 leaves the
door open exactly this far; §7 Q1 asks for the ratification):

- The decoder **already exists in this package**:
  `parseJailReports` (`src/workers/validator-sampler/decode.ts:77-94`) parses
  the contract's `jail_reports {}` smart query, returning
  `{valoper, reportedAtSeconds, purgeReadyAtSeconds}`. The design-note line
  "each needs a live decoder this PR does not add"
  (`incidents.ts:14-17`) predates the validator-sampler; the parse is now a
  same-package reuse, not a build.
- The read is one more `smartAtHeight` on the pinned client the reconciler
  already holds and already calls twice per pass (`reconciler/index.ts:39-54`).
  Bounded: reports ≤ the contract's validator bound.
- Derivation is closeable per report, dedupeKey
  `valoper:{addr}:{reportedAtSeconds}` (§4b C1 — the *episode* is the natural
  key: `store.ts:76-83`'s reopen-in-place keeps the original `openedAt`, so a
  bare `valoper:{addr}` key would silently merge a re-jail into the first
  episode's record, the M6.4 overwrite shape). Open while the report exists;
  closed when it no longer does (purged or cleared). Severity `warning`.
- The downstream is, again, already built: `jail_report →
  validator_set_incident` (`alerts.server.ts:173`), Learn history copy
  (`incident-history.tsx:22`).
- Its **live drill cannot run per-PR** — `jail-drill.sh` "can produce a jailed
  validator only on a chain reset for that purpose, which would destroy the
  state every other live spec runs against"
  (`2026-07-24-app-m6.4-operator-view.md:619-622`; the drill needs a
  default-slash-window chain, `infra/devnet/dev-node.sh:36-38`,
  `contracts/IMPLEMENTATION-STATUS.md:375-379`) — which is exactly why D30
  routes it to the dedicated-chain lane (§2.7). Its per-PR gates are the unit
  suite and the Postgres alarm-suite extension; the lane observes it live.

**`epoch_overdue` is not cheap — recommend it stays recorded** (the D30
default):

- The derivation itself is moderate: a UTC civil-month boundary mirror (the
  `nextEpochIso` shape, `apps/web/app/stake/stake.server.ts:29-33`) plus a
  slack constant. But the slack is a **new tolerance-class correctness
  contract** (§9.5.6/§12.1 — how late is "overdue" for a calendar-month
  epoch?) with no measured basis to set it from.
- Decisively: **no falsifiable drill exists.** An overdue epoch requires a
  calendar-month boundary to pass with the crank withheld. A mid-month fresh
  chain cannot produce one (the E-CAL constraint that already blocks corpus
  regeneration, overview CO-30), per-PR CI cannot, and even the monthly lanes
  would have to deliberately withhold the epoch crank across a real month
  rollover. A kind whose alarm can never be exercised fails this plan's own
  drill rule. The honest home for its first exercise is Phase B's T1
  calendar-month observation window (overview §2 — the pause "naturally spans
  calendar-month boundaries"; §5 T1.6), and the recording in
  `indexer-design-notes.md` is rewritten to say exactly that (§6).

### 2.6 The drill driver: orchestration on the host, observation in the specs

Playwright runs in its own container on the `nvhash-dev` network
(`compose.yaml:47-58`) with no Docker socket — a spec can reach
`web:3000` / `api:8080` / `postgres:5432` but cannot stop a container. So the
split is: **a host-side driver sequences the failures; the specs only observe
HTTP.** No pg client or Docker dependency is added to `apps/web` (dependency
additions are reviewed events, SECURITY.md).

New `infra/devnet/drills.sh` (the `stack.sh` conventions: `set -euo
pipefail`, shellcheck-clean for the `shell-lint` job):

```
drills.sh run           # the full sequence below
drills.sh <phase>       # one phase, for iteration
```

Sequence: `baseline` (stack healthy, web freshly restarted per §2.8, drill
specs assert the *absence* of every degraded state — the control that proves
the later positives are caused, not ambient) → `corrupt-row` (SQL via
`docker compose exec postgres psql`; poll `/api/v1/incidents` until the
divergence opens, bounded wait; run the phase spec) → `repair` (reverse SQL;
assert close + banner clear) → `indexer-kill` (`compose stop indexer`; wait
past `DEGRADED_STALE_SECONDS`; phase spec) → `indexer-recover` (`compose
start indexer`; assert banner clears) → `lcd-kill` (`docker stop dev-node`;
phase spec) → `lcd-recover` (`docker start dev-node`; assert full recovery —
this phase is what proves §2.3's restart policy: the indexer must come back
without hands) → `bell` (§2.9). The driver **refuses to run** unless the
chain reports `chain-dev`'s chain-id family (SECURITY.md: "Drill scripts
assume a disposable local chain; point them at nothing else").

Spec side: `apps/web/e2e-live/drills/degradation.spec.ts` (new), gated by
`E2E_DRILL_PHASE`. The gating helper **fails rather than skips** when
`E2E_DRILL_PHASE` names a phase whose expected state is absent — a drill that
skips is silence, and every drill must FAIL when the honesty machinery is
silent. With `E2E_DRILL_PHASE` unset the file skips clean like every other
e2e-live spec, so `test:e2e:live` remains runnable standalone.

Every degraded-phase spec also asserts CO-23: the `/market` forthcoming shell
and the `/exit` DEX coming-soon shell still render as labeled states (the
offline assertions in `e2e/market.spec.ts` / `e2e/exit.spec.ts` are the
model), never blank and never an error page.

shows the jailed validator's state honestly; the `jail_report` incident is

### 2.8 The stale-bundle fix is a mechanism, not a reminder

The trap (`web-design-notes.md:222-234`): the compose `web` service builds at
container **start** (`compose.yaml:180-183`), so a long-running stack serves a
stale bundle and a green live run can certify code that is not there —
it has already happened once (guard assertions "passing" against a build
without the allowlist entry). Today's remedy is a sentence in two files
telling a human to restart. Commit C/D replace the reminder with machinery:

- `stack.sh e2e` (new subcommand): `docker compose --profile app --profile db
  restart web` → wait healthy → export `E2E_LIVE_STACK_PREPARED_AT=<epoch>` →
  run the requested suites. The lane and `drills.sh` call **only** this entry.
- `/healthz` (`app/routes/healthz.tsx`) gains `started_at` — the server
  module's load time, which under the compose command is strictly after the
  build that produced it.
- `apps/web/e2e-live/drills/stale-bundle.spec.ts` (new) runs **first** in
  every prepared session and FAILS if `started_at` predates
  `E2E_LIVE_STACK_PREPARED_AT` — a green run on a stale bundle is now
  unrepresentable through the entry point, and a bypassed entry point fails
  the gate rather than passing silently. (Unset, the spec skips clean like
  its siblings, so ad-hoc local runs keep working — with the documented
  manual restart as before.)

### 2.9 The drill → notifier tick → bell chain, finally end to end (CO-14)

M6.2 shipped the chain gated by the pure `test/notifier.test.ts` because "a
notifier tick is a separate worker process" (`m6.2:515-519`). §1 item 3 shows
why it stayed that way: the stack never ran the process, and the web tier's
store wasn't durable, so there was no shared table for the bell to read.
Commit C completes the substrate; commit D drives the chain:

## 4. Security & invariants (enforced mechanisms with gating tests)

Tests marked **(new)** do not exist today; everything else is standing. Every
honesty invariant carries what a **silent failure would hide from users** —
the drill-flavored attacker-gain line (overview §8): the "attacker" here is
any defect that lets the app lie, and the gain is what users would do while
believing it.

1. **Every drill FAILS on silence.** A phase spec asserts the *positive
   presence* of the labeled degraded state; the `phase.ts` gate **(new)**
   throws instead of skipping when its phase is active; the `baseline` phase
   asserts the absence of every degraded state first, so a positive is caused,
   not ambient. *Gates:* `drills/degradation.spec.ts` **(new)** + the driver's
   exit code. *Silent failure hides:* everything below at once — a drill
   harness that skips is the honesty machinery's own honesty gap.
2. **A corrupted mirror cannot be presented as authoritative.** Corrupt row →
   `reconciler_divergence` ≤ 2 cadences → degraded banner; repair → close →
   clear. *Gates:* `test/integration/reconciler-alarm.test.ts` (standing,
   both directions) + the `corrupt-row`/`repair` phases **(new)**. *Hides:*
   fabricated history and NAV-bearing figures rendered as fact — a holder
   values, buys, or redeems against numbers the chain never produced.
3. **The data's age is the data's age.** `/status.reconciled_at` is the
   reconciler run's `ranAt`, never the response clock; the footer age derives
   from it. *Gates:* `test/envelope-contract.test.ts` + `test/derive.test.ts`
   extensions **(new cases)**; `test/freshness.test.ts` **(new cases)**.
   *Hides:* a dead indexer serving week-old figures under "(0s ago)" — a user
   times an exit against a redemption queue that no longer exists.
4. **A dead reconciler cannot certify freshness.** Heads older than
   `DEGRADED_STALE_SECONDS` flip the chrome to degraded even though the
   height delta is frozen. *Gates:* the generated chrome matrix **(new)** +
   the `indexer-kill` phase **(new)**. *Hides:* same as 3, at the banner
   level — "history dims" was a plan sentence with no mechanism until this.
5. **A failed live read never fabricates program health.** No paused/halted
   banner without a successful live read; footer says "Program status
   unavailable"; live figures "n/a", never 0; the degraded banner needs no
   live health (it is the indexed plane's own claim). *Gates:*
   `test/chrome-state.test.ts` (standing rules, regenerated in the matrix) +
   the `lcd-kill` phase **(new)** + the standing offline live-down instance.
   *Hides:* a paused vault rendered unpaused — a depositor sends funds into a
   vault that will hold them, the exact §14.6 danger the paused banner exists
   to prevent.
6. **`vault_paused` is derived from live truth and closes only on observed
   truth.** Closeable on the vault read; an unreadable vault yields a skipped
   pass, never a close (an unknown pause state is not "unpaused"). *Gates:*
   `test/reconciler/reconciler.test.ts` pause + skipped-pass cases **(new)**;
   `reconciler-alarm.test.ts` pause extension **(new)**; the lane's pause
   drill **(new)**. *Hides:* a pause with no durable record — Learn's
   incident history and the alerts chain stay silent, and post-incident
   accountability ("when, and why, was the vault paused?") has no answer.
7. **The alarm outlives what it watches.** A failed pass is logged and
   skipped, not fatal (`runReconciler` catch **(new behavior)**); the compose
   restart policy makes the worker-crash contract true. *Gates:* skipped-pass
   unit case **(new)**; the `lcd-recover` phase asserts unattended recovery
   **(new)**. *Hides:* one LCD blip permanently silencing ingestion *and* the
   alarm while the API serves frozen data as fresh — the compound lie of §2.2
   with no bound on its duration.
8. **The notification chain has no in-memory link.** Fact → API internal read
   → notifier tick → Postgres row → bell, every hop the production
   implementation. *Gates:* `test/notifier.test.ts` (standing, pure core) +
   `drills/bell.spec.ts` **(new)** + the standing exactly-once constraint.
   *Hides:* users opted into alerts hearing nothing — a redemption matures,
   a vault pauses, and the subscriber the program promised to tell is told
   nothing, silently.
9. **A green live run certifies the bundle it ran against.** The `stack.sh
   e2e` entry restarts `web`; `started_at` must postdate
   `E2E_LIVE_STACK_PREPARED_AT`. *Gates:* `drills/stale-bundle.spec.ts`
   **(new)**. *Hides:* a suite blessing code that is not deployed — a guard
   regression ships behind a green checkmark (it nearly did once,
   `web-design-notes.md:225-228`).
10. **`group_policy_info` semantics are pinned by a live chain, not a guess.**
    The plain-account probe asserts 404, matching the offline mock and the
    admin-gate's 404-only rule. *Gates:* the CO-17 assertion in
    `e2e-live/governance.spec.ts` **(new)**. *Hides:* if the build's
    assumption is wrong, `not-governed` is unreachable — admin and governance
    surfaces render "we could not check" forever, degraded-as-normal.
11. **Drills point only at disposable chains; keys stay throwaway.**
    `drills.sh` and `e2e-keys.sh` refuse off-devnet by chain-id; the lane's
    chains are reset-created and torn down; the signer sentinel scan keeps
    test keys out of bundles. *Gates:* the scripts' guards (reviewed shell,
    `shell-lint` job) + `check:bundle` (standing). *Hides:* n/a — this one is
    a containment control; what it prevents is the harness itself becoming
    the incident.
12. **No new PII, no schema change.** New incident rows carry operational
    payloads (`reason`, valoper, report timestamps — public chain facts);
    the `IncidentKind` enum values already exist in the baseline migration;
    no column is added anywhere. *Gates:* `test/schema-allowlist.test.ts`,
    `app-schema-allowlist.test.ts`, log-scrubbing (all standing).
13. **Standing gates continue** and the drill family joins the honest side of
    them: `pnpm -r` typecheck/test stays Postgres-free (all new integration
    coverage lives in the `test:grants`/`test:db`/lane homes), offline
    `web-e2e` runtime is unchanged, Biome/shellcheck clean.

**Nullable-gates-affordance review (overview §8, answered per nullable):**

- `ChromeState` inputs `live` / `freshness` / `incidents` are each
  `T | null`, and **null means "unknown", never "no"**: null `live` → no
  paused/halted banner *and* the explicit "Program status unavailable" line
  (unknown suppresses the *claim*, and says so — it never asserts health);
  null `freshness` → footer "n/a", no lag computation; null `incidents` → no
  incident-driven banner and no "no incidents" claim. Conservative in the
  only direction that is honest for an *informational* surface: absence of a
  warning is never presented as evidence of health (invariant 5's footer line
  is the compensating signal).
- `reconciled_at === null` → cold start (no run row exists), which is a
  distinct honest state and deliberately **not** degraded (`lag.ts:38-47`);
  it cannot coexist with non-null heads (§2.2), and the matrix asserts that
  pairing is unrepresentable.
- `IncidentRow.closed_at ?? null` gates the degraded banner (open = null):
  null means **"still open" — a positive fact from the sole writer**, not
  unknown; an unfetchable feed is the `incidents: null` case above, already
  conservative.

## 4b. Completeness obligations (overview §8, format v2 per D26)

### C1 — Natural keys & cardinality

| Key / collection | Uniqueness | Max multiplicity | Handling |
| --- | --- | --- | --- |
| `vault_paused` dedupeKey `"paused"` | one live pause condition | 1 open at a time; reopens over time | the `contract_halted` shape: upsert reopens (`store.ts:76-83`); episode history is the open/close timestamps in the row plus `reconciler_runs` |
| `jail_report` dedupeKey `valoper:{addr}:{reportedAtSeconds}` | one row per **episode** | N validators × M episodes each | episode in the key — `valoper:{addr}` alone would reopen-in-place and merge a re-jail into the first episode's `openedAt` (the M6.4 overwrite shape); *disproof: two jailings of one validator that must both survive as records* |
| Drill phases | one observed state per phase | phases strictly sequential | driver serializes; `workers: 1` in the live config (standing) |
| Notifications per drill | `(address, kind, dedupeKey)` unique (standing) | re-running the bell drill inserts nothing new | exactly-once is the standing constraint; the spec asserts presence, not count-of-one across runs |

### C2 — Wire bounds

No new collection endpoint. `/status.reconciled_at` is a scalar. New incident
rows ride the existing paginated `/incidents` under the shared page cap;
`jail_report` per-pass reads are bounded by the contract's validator bound
(the `MAX_PROGRAM_VALIDATORS` mirror); the notifier fact page stays clamped
(`factLimit` ≤ 500, standing). *Gate:* standing bounds suites; nothing to
extend in `bounds.ts`.

### C3 — Concurrency

| Read-then-write / race | Remedy |
| --- | --- |
| Reconciler pass vs drill SQL corrupting the compared row | none needed: `applyActions` is one transaction (standing); the drill polls for the incident rather than assuming pass timing |
| Corruption vs worker replay "healing" the row | does not occur: the epoch-history cursor is past the crank height, so nothing rewrites the corrupted row until `repair` (stated in `drills.sh`, so nobody "fixes" the drill by re-ingesting) |
| Two reconciler instances (drill restart racing a live pass) | single service instance in compose; incident upsert on `(kind, dedupeKey)` is idempotent either way (standing `@@unique`) |
| Notifier tick vs web read of the bell | `commitTick` inserts + cursor in one transaction (standing); the bell read is after-commit by construction |
| Lane vs lane | one concurrency group in `live-lane.yaml`; the jail chain is created and destroyed inside its own job |

### C4 — State × affordance (generated, not tabulated)

The touched UI surface is the chrome. `test/chrome-state.test.ts` is rebuilt
to **generate** its cases over the loader's own inputs — exactly the four
nullable/enumerable inputs `loadChromeState` consumes:

```
{live: ok-nominal | ok-paused | ok-halted | failed}
× {status: ok-fresh | ok-stale | ok-coldstart | failed}
× {incidents: none-open | divergence-open | lag-open | failed}
```

(48 cells; the generator derives expected `{banner, liveStatusOk, footer}`
from the precedence rule halted > paused > degraded plus invariant 5's
suppression rules, and asserts every cell — the missing-input case is already
carried in the types as `null`, so the compiler forces every consumer today;
what the generator adds is that no *combination* goes unasserted, the M7.5–7.6
round-2 lesson.) The bell feed's `Map | null` ack matrix is standing
(`admin-data.test.ts`) and untouched.

### C5 — Plane precedence

The drills are C5's executable form. Restated for the three phases: live
decides program health and never yields it to the mirror (lcd-kill: mirror
keeps serving, no banner is fabricated *from* it); the mirror decides history
and never claims currency (indexer-kill: live survives, the mirror's claim
visibly ages); an open divergence incident is the mirror confessing about
itself and outranks its own data (corrupt-row). `liveState`-vs-`plane`
(governance) is standing and not touched.

### C6 — Temporal spans

| Span | Handling |
| --- | --- |
| Incident open→close | timestamps from the pass clock (standing); drill asserts both edges |
| `reconciled_at` age vs `DEGRADED_STALE_SECONDS` | threshold = 10× cadence so one late pass never flips it; the drill waits past threshold + one cadence, bounded |
| Jail episode | `reportedAtSeconds` in the key (C1); `purgeReadyAtSeconds` rides the payload |
| Drill waits | every driver poll has a bounded timeout that FAILS the phase — no unbounded "eventually" |
| Bell delivery | ≤ 2 ticks at `NOTIFIER_TICK_SECONDS=10`, bounded assert |

### C7 — Gate property (for every mechanism above: the test, and what breaking it fails)

| --- | --- | --- |

# M8.4 Indexer Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy `services/indexer` to `provlabs-test` (and scaffold `provlabs-prod`) as a container image under an ArgoCD Helm chart, driven by the shared ProvLabs build/promote workflows.

**Architecture:** A multi-stage Dockerfile reproduces the ADR-002 dev execution path exactly (TypeScript run directly on Node type stripping, no build step). A Helm chart under `services/indexer/argocd/` runs one replica with a `cloud-sql-proxy` native sidecar using IAM auth — so the chart carries no secret material — and a migrate initContainer sharing the app container's digest. Two thin GitHub Actions callers hand off to `ProvLabs/gha-workflows`.

**Tech Stack:** Node 22 (`node:22-bookworm-slim`), pnpm 11 workspace, Prisma 6, Helm 3, ArgoCD, Cloud SQL + `cloud-sql-proxy` 2.17.1, Vitest, GitHub Actions.

**Spec:** [`2026-08-17-app-m8.4-indexer-deployment-design.md`](2026-08-17-app-m8.4-indexer-deployment-design.md) — read it before Task 1. Every "why" in this plan is argued there.

## Global Constraints

Every task's requirements implicitly include this section.

- **All JS/TS tooling runs in containers, never on the host** (ADR-002). Use the repo-root wrapper: `./dev pnpm …`, `./dev node …`, `./dev pg up|reset`. Host `node`/`pnpm` are deliberately not load-bearing and `node_modules` holds Linux binaries. `docker` and `helm` commands run on the host normally — they are not JS tooling.
- **Comment standard is normative** ([`docs/architecture/comment-standard.md`](../architecture/comment-standard.md)). **Do not write delivery provenance into any file** — no "M8.4", no "PR 8.4", no "plan §2.2", no dates. Cite durable authorities instead: an ADR, a spec section, a `chain-facts` entry, or the gating test that pins the behavior. Every exported symbol carries a contract doc comment.
- **`SECURITY.md` is normative** and its hook fires on these paths. Security controls must be **enforced mechanisms with gating checks, never caller or topology assumptions**. No credential may be committed outside `.env.example` placeholders and the `infra/dev/` devnet exception.
- **Formatting/linting is one repo-wide tool.** `./dev pnpm run lint` to check, `./dev pnpm run lint:fix` to apply. Biome covers JS/TS/CSS only — the YAML and SQL in this plan are not auto-formatted, so match surrounding style by hand. A formatting-only diff fails CI.
- **Every tracked `*.sh` is shellcheck-gated** at `--severity=warning` by the `shell-lint` job. New scripts must pass.
- Base image: `node:22-bookworm-slim`, digest-pinned, **kept in lockstep** with `infra/dev/compose.yaml` and the `app-ci.yaml` job containers.
- Chart name and `argo-app` are both exactly `nvhash-indexer`.
- Required runtime env in the image: `NODE_OPTIONS=--experimental-transform-types` (non-optional — `src/runtime/streams.ts` uses TS parameter properties that strip-only mode rejects), `NODE_ENV=production`, `INDEXER_HEARTBEAT_FILE=/heartbeat/indexer.heartbeat`.
- The chart contains **no `SealedSecret` and no `Service`**. `replicas: 1` and `strategy.type: Recreate` are correctness requirements, not preferences.
- Workflow inputs: `reproducible: false`, `build-cache: true`, `auto-merge: false`.

### Hard external blocker: 8.4a's Prisma baseline-mode exit

Every task below can be built and merged, but **the chart must not be synced to a
real environment until 8.4a's Prisma half lands.** `services/indexer/CLAUDE.md`
currently specifies the `indexed` schema as ONE regenerated baseline migration
rather than an append-only history, on the stated grounds that no deployed
database exists. Task 4's migrate initContainer runs `prisma migrate deploy`,
and a *regenerated* baseline cannot be applied to a populated database — the
first schema change after the first deploy fails the initContainer and the Pod
never starts.

8.4a's contract half has landed (`f27943f`, the wasmd `migrate` entry point);
the baseline-mode exit has not. Two acceptable paths, and the choice must be
recorded rather than discovered:

1. 8.4a lands first, and this branch merges after it.
2. This branch merges and the first testnet sync is treated as a one-time
   empty-database bootstrap, with 8.4a required before *any* subsequent schema
   change. Task 8 Step 2 amends the `CLAUDE.md` rule either way.

- [ ] **Step 7: Extract `buildWorkers` in `src/index.ts` and wire the start height**

In `src/index.ts`, lift the `workers` array out of `run()` into an exported function placed just above `run()`. Replace the inline `const workers: Worker[] = [ … ]` block with a call.

```ts
/**
 * The composition root's worker set. Exported so the start-height wiring is
 * assertable: a stream left at the `startHeight` default pages from height 1,
 * which on a chain with millions of blocks never converges. Pinned by
 * test/workers/build-workers.test.ts.
 *
 * @param config validated indexer configuration
 * @param deps chain transports the workers read through
 * @returns one worker per ingestion stream, each with an explicit start height
 */
export function buildWorkers(
  config: IndexerConfig,
  deps: { rpc: RpcClient; pinned: PinnedLcdClient },
): Worker[] {
  const { rpc, pinned } = deps;
  const startHeight = BigInt(config.indexStartHeight);
  return [
    createChainEventsWorker({
      rpc,
      startHeight,
      scope: {
        vaultAddress: config.vaultAddress,
        receiptDenom: config.receiptDenom,
        contractAddress: config.contractAddress,
      },
    }),
    createEpochHistoryWorker({
      rpc,
      pinned,
      startHeight,
      contractAddress: config.contractAddress,
    }),
    createValidatorSamplerWorker({
      rpc,
      pinned,
      startHeight,
      contractAddress: config.contractAddress,
    }),
    // Governance starts on every chain, including one with no x/group substrate
    // at all: policy discovery then resolves to the empty set and the worker
    // commits empty windows, the honest no-governance state rather than a crash
    // or a silently disabled stream.
    createGovernanceWorker({
      rpc,
      pinned,
      contractAddress: config.contractAddress,
      lcdUrl: config.lcdUrl,
      overridePolicies: config.govGroupPolicies,
      startHeight: BigInt(config.govStartHeight),
    }),
  ];
}
```

Inside `run()`, replace the removed block with:

```ts
  const workers = buildWorkers(config, { rpc, pinned });
```

Add `IndexerConfig` to the existing `./config.ts` import (`import { type IndexerConfig, loadConfig } from "./config.ts";`).

```dockerfile
# syntax=docker/dockerfile:1

# Runtime image for the chain-event indexer.
#
# The service runs its TypeScript sources directly on Node's type stripping;
# there is deliberately no build step (ADR-002,
# docs/architecture/2026-07-14-adr-002-containerized-dev-toolchain.md). This
# image keeps that property: the same base as the dev tools plane and the
# app-ci job containers, the same sources, the same flags — so "works under
# ./dev" and "works in the cluster" are one claim.
#
# The base digest is pinned by hand; there is no automation. Re-resolve with:
#   docker buildx imagetools inspect node:22-bookworm-slim
# Use the `Digest:` line (the multi-arch index digest, which is what FROM
# pins). Do NOT use `docker manifest inspect -v` — it returns one descriptor
# per platform and gives the wrong value.
#
# Keep the base tag in LOCKSTEP with infra/dev/compose.yaml and the container
# images in .github/workflows/app-ci.yaml.

FROM node:22-bookworm-slim@sha256:<DIGEST> AS base
ENV COREPACK_ENABLE_DOWNLOAD_PROMPT=0
WORKDIR /app

FROM base AS deps
# Manifests and the lockfile only, so this layer is keyed on dependencies and
# survives source-only commits.
#
# Every workspace manifest is copied, not just the indexer's:
# --frozen-lockfile validates the lockfile's importers against the manifests
# present, and a filtered install with manifests missing reports the lockfile
# as out of sync. Listing them means adding a workspace package fails HERE,
# loudly, rather than drifting. pnpm-workspace.yaml is required for --filter to
# resolve anything at all.
COPY pnpm-lock.yaml pnpm-workspace.yaml package.json ./
COPY services/indexer/package.json services/indexer/
COPY apps/web/package.json apps/web/
COPY services/api/package.json services/api/
COPY packages/api-types/package.json packages/api-types/
COPY packages/chain-client/package.json packages/chain-client/
COPY packages/db-indexed/package.json packages/db-indexed/
COPY packages/fixtures/package.json packages/fixtures/
RUN corepack pnpm install --frozen-lockfile --filter @nvhash/indexer

FROM deps AS build
COPY services/indexer/ services/indexer/
# --generator=client selects the client generator ONLY. The schema also
# declares a `dbIndexed` generator whose output is
# packages/db-indexed/generated/client; running it would require that package
# in the build context. Selecting the generator keeps packages/ out of the
# image.
RUN corepack pnpm --filter @nvhash/indexer exec prisma generate --generator=client

FROM base AS final
# Transform mode, not strip-only: src/runtime/streams.ts uses TS parameter
# properties, which Node's default strip-only type stripping rejects.
ENV NODE_OPTIONS=--experimental-transform-types \
    NODE_ENV=production \
    INDEXER_HEARTBEAT_FILE=/heartbeat/indexer.heartbeat

COPY --from=build --chown=node:node /app /app
USER node

# Dev dependencies are NOT pruned: the `prisma` CLI and prisma/migrations in
# this image are what the deployment's migrate initContainer runs, which is
# what makes schema and code the same digest by construction.
#
# The entrypoint bypasses `pnpm run start` on purpose. That script is
# `prisma generate && node src/index.ts`; generating at container start would
# require a writable tree and defeat readOnlyRootFilesystem. Generation happens
# in the `build` stage above.
CMD ["node", "services/indexer/src/index.ts"]
```

### Task 3: Cloud SQL role bootstrap

The deployed analogue of `infra/dev/postgres/roles.sql`. Credential-free, because only IAM principals authenticate. Design §2.2.

**Files:**
- Create: `infra/cloudsql/roles.sql`
- Create: `infra/cloudsql/README.md`

**Interfaces:**
- Consumes: nothing.
- Produces: roles `indexer_writer` / `api_reader` / `app_writer` (all `NOLOGIN`), schema ownership, and the default-role assignment that makes Prisma's migrations create `indexer_writer`-owned tables.

- [ ] **Step 1: Write the bootstrap SQL**

Create `infra/cloudsql/roles.sql`:

```sql
-- Two-domain role + schema bootstrap for a deployed (Cloud SQL) database
-- (ADR-001 Decision 1: one PostgreSQL instance, two ownership domains enforced
-- by roles, not convention). Applied by hand once per environment, before the
-- first sync of any component. Safe to re-run.
--
-- This file contains NO credentials, and cannot: the three domain roles are
-- NOLOGIN. Authentication is Cloud SQL IAM — cloud-sql-proxy runs with
-- --auto-iam-authn and each component connects as its own IAM principal. The
-- domain roles exist only to own objects and carry grants. (Contrast
-- infra/dev/postgres/roles.sql, whose throwaway LOGIN passwords are permitted
-- solely by SECURITY.md's development-environment exception.)
--
-- Ownership map (ADR-001 Decision 1):
--   indexed  -> indexer_writer  (sole DDL/DML; the only writer of history)
--   app      -> app_writer      (sessions/alerts/notifications/push; no grants
--                                on indexed of any kind)
--   api_reader -> USAGE + SELECT on indexed only; no write grant anywhere.
--
-- The boundary this file establishes is asserted by
-- services/indexer/test/integration/grant-boundary.test.ts, which pins the
-- same properties against the dev substrate.
--
-- PROJECT SUBSTITUTION: replace @provlabs-test with the target project in the
-- three IAM principal names below. Cloud SQL IAM users are named for the
-- service account with the `.gserviceaccount.com` suffix removed.

-- Domain roles. NOLOGIN: nothing authenticates as these.
DO $$
BEGIN
  IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'indexer_writer') THEN
    CREATE ROLE indexer_writer NOLOGIN;
  END IF;
  IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'api_reader') THEN
    CREATE ROLE api_reader NOLOGIN;
  END IF;
  IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'app_writer') THEN
    CREATE ROLE app_writer NOLOGIN;
  END IF;
END
$$;

-- Schemas, each owned by its writer role. Owning the schema is what lets a
-- migration running as that role create tables/types it — and only it — owns.
CREATE SCHEMA IF NOT EXISTS indexed AUTHORIZATION indexer_writer;
CREATE SCHEMA IF NOT EXISTS app AUTHORIZATION app_writer;
ALTER SCHEMA indexed OWNER TO indexer_writer;
ALTER SCHEMA app OWNER TO app_writer;

-- No ambient rights.
REVOKE ALL ON SCHEMA indexed FROM PUBLIC;
REVOKE ALL ON SCHEMA app FROM PUBLIC;

-- api_reader: read-only visibility into indexed and nothing else. Default
-- privileges keyed to indexer_writer extend SELECT to every table a later
-- migration creates. No INSERT/UPDATE/DELETE is ever granted.
GRANT USAGE ON SCHEMA indexed TO api_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA indexed TO api_reader;
ALTER DEFAULT PRIVILEGES FOR ROLE indexer_writer IN SCHEMA indexed
  GRANT SELECT ON TABLES TO api_reader;

-- The write boundary is enforced by ABSENCE of grants, made explicit:
--   * app_writer has no USAGE/SELECT on indexed  -> cannot read history.
--   * api_reader has no USAGE on app             -> cannot see app state.
--   * indexer_writer has no USAGE on app         -> the two-reader invariant
--     (ADR-001 Decision 3).
REVOKE ALL ON SCHEMA indexed FROM app_writer;
REVOKE ALL ON SCHEMA app FROM api_reader;
REVOKE ALL ON SCHEMA app FROM indexer_writer;

-- IAM principal -> domain role. The GRANT alone is not sufficient: a session
-- authenticating as the IAM principal would still CREATE objects owned by that
-- principal, not by the domain role, silently breaking the ADR-001 ownership
-- split and the default privileges above (api_reader would not see the new
-- tables). SET role makes every session for that principal start as the owning
-- role, so migrations create correctly-owned objects.
GRANT indexer_writer TO "nvhash-indexer@provlabs-test.iam";
ALTER ROLE "nvhash-indexer@provlabs-test.iam" SET role = indexer_writer;

-- The api and web tiers, granted here so the boundary is established in one
-- place. Their deployments land in their own changes; the grants are inert
-- until those principals exist, so run the matching pair per component as it
-- is provisioned.
-- GRANT api_reader TO "nvhash-api@provlabs-test.iam";
-- ALTER ROLE "nvhash-api@provlabs-test.iam" SET role = api_reader;
-- GRANT app_writer TO "nvhash-web@provlabs-test.iam";
-- ALTER ROLE "nvhash-web@provlabs-test.iam" SET role = app_writer;
```

- [ ] **Step 1: Write the failing assertion**

Append a new `describe` block at the end of `services/indexer/test/integration/grant-boundary.test.ts`:

```ts
// Table OWNERSHIP, not just grants. api_reader's SELECT on future tables comes
// from default privileges keyed to indexer_writer, so a table created by any
// other role is invisible to the API even though every grant above still
// passes. In a deployed environment the migration authenticates as an IAM
// principal, and only `ALTER ROLE … SET role = indexer_writer` keeps ownership
// correct; this asserts the property that line exists to produce.
describe("indexed schema ownership", () => {
  it("has at least one table to assert on", async () => {
    const { rows } = await client.query<{ count: string }>(
      "SELECT count(*)::text AS count FROM pg_tables WHERE schemaname = 'indexed'",
    );
    expect(Number(rows[0]?.count ?? "0")).toBeGreaterThan(0);
  });

  it("is owned entirely by indexer_writer", async () => {
    const { rows } = await client.query<{ tablename: string; tableowner: string }>(
      `SELECT tablename, tableowner FROM pg_tables
        WHERE schemaname = 'indexed' AND tableowner <> 'indexer_writer'
        ORDER BY tablename`,
    );
    expect(rows).toEqual([]);
  });

  it("keeps the schema itself owned by indexer_writer", async () => {
    const { rows } = await client.query<{ owner: string }>(
      `SELECT pg_get_userbyid(nspowner) AS owner
         FROM pg_namespace WHERE nspname = 'indexed'`,
    );
    expect(rows[0]?.owner).toBe("indexer_writer");
  });
});
```

- [ ] **Step 2: Bring up the dev database, apply the boundary, migrate AS `indexer_writer`**

The role the migration runs as is the whole point of this test, so set
`DATABASE_URL` explicitly. A migration run as the `nvhash` superuser creates
`nvhash`-owned tables and the new assertion will (correctly) fail — that is the
test working, not a bad test.

```bash

./dev pg up

  psql "postgresql://nvhash:nvhash-dev@localhost:5432/nvhash" -v ON_ERROR_STOP=1 \
  < infra/dev/postgres/roles.sql
docker compose -f infra/dev/compose.yaml run --rm \
  -e DATABASE_URL="postgresql://indexer_writer:indexer-dev@postgres:5432/nvhash?schema=indexed" \
  tools corepack pnpm --filter @nvhash/indexer run migrate:deploy
```

Two mechanics that are easy to get wrong, both verified during execution:

- **`./dev` does not forward host environment variables.** It is
  `docker compose run --rm tools "$@"` with no `-e` passthrough, so
  `DATABASE_URL=… ./dev pnpm …` silently runs without the variable and Prisma
  fails with a `getConfig` validation error. Invoke compose directly with `-e`
  as above — still the same pinned container, so ADR-002 holds.
- **Host names differ by vantage point.** `postgres:5432` is the compose service
  name, resolvable from inside the tools container; the `psql` call runs *inside*
  the postgres container, hence `localhost:5432`; host-side tooling would use
  `localhost:5433`.

- [ ] **Step 1: Write the scanner**

Create `infra/scripts/check-no-committed-secrets.sh`. First-party rather than a third-party action, per SECURITY.md's preference for first-party tooling and minimal dependency surface.

```bash
#!/usr/bin/env bash
# Fail if a tracked file carries credential-shaped content outside the two
# places that are allowed to: `.env.example` placeholders and the throwaway
# devnet substrate under infra/dev/ (SECURITY.md development-environment
# exception).
#
# Deployed component charts must hold NO secret material at all: database
# access is Cloud SQL IAM auth, so a SealedSecret or an inline password in a
# values file is a design regression, not a configuration choice.
set -euo pipefail

fail=0

report() {
  printf 'SECRET SCAN: %s\n' "$1" >&2
  fail=1
}

# 1. Component charts must carry no sealed-secret or password material.
while IFS= read -r file; do
  if grep -nEi 'secretToml|encryptedData|kind:[[:space:]]*SealedSecret|PASSWORD[[:space:]]*=' "$file"; then
    report "$file carries secret material; deployed charts use IAM auth"
  fi
done < <(git ls-files 'services/*/argocd/*' 'apps/*/argocd/*')

# 2. No private keys anywhere.
while IFS= read -r file; do
  if grep -nE -- '-----BEGIN [A-Z ]*PRIVATE KEY-----' "$file"; then
    report "$file contains a private key block"
  fi
done < <(git ls-files)

# 3. Password-shaped assignments outside the allowed homes.
while IFS= read -r file; do
  case "$file" in
    *.env.example|infra/dev/*|infra/devnet/*) continue ;;
    infra/scripts/check-no-committed-secrets.sh) continue ;;
  esac
  if grep -nEi "(password|passwd|secret_key|api_key|token)[[:space:]]*[:=][[:space:]]*['\"][^'\"]{8,}" "$file"; then
    report "$file assigns a credential-shaped literal"
  fi
done < <(git ls-files '*.yaml' '*.yml' '*.sql' '*.ts' '*.tsx' '*.js' '*.mjs' '*.toml' '*.sh')

if [ "$fail" -ne 0 ]; then
  printf 'SECRET SCAN FAILED\n' >&2
  exit 1
fi
printf 'secret scan clean\n'
```

Converts the single-writer and no-HTTP properties from reviewed YAML into a check that fails when a future edit reintroduces `RollingUpdate` — the most likely regression here, because it is the Kubernetes default and reads as an improvement. **Do not start without an explicit decision** — it modifies `app-ci.yaml`.

**Files:**

- Modify: `.github/workflows/app-ci.yaml`

**Interfaces:**
- Consumes: Tasks 4 and 5 (the chart must render).
- Produces: nothing.

- [ ] **Step 1: Write the checker**

Create `infra/scripts/check-chart-invariants.sh`:

```bash
#!/usr/bin/env bash
# Assert the deployment invariants of the indexer chart against its RENDERED
# output, for every environment's values.
#
# These are correctness properties, not style:
#   * exactly one replica, and Recreate rather than RollingUpdate — the running
#     marker NAV is an unconditional last-write-wins upsert
#     (services/indexer/src/workers/chain-events/store.ts), so two overlapping
#     supervisors can stamp a stale NAV over a newer one;
#   * no Service and no container port — the indexer serves no HTTP to anyone;
#   * every container read-only-root and non-root;
#   * the migrate initContainer on the SAME image reference as the app
#     container, which is what makes schema and code the same commit.
set -euo pipefail

CHART=services/indexer/argocd
fail=0

check_env() {
  local env_name="$1" rendered
  rendered="$(helm template nvhash-indexer "$CHART" \
    -f "$CHART/values.yaml" \
    -f "$CHART/values-${env_name}.yaml" \
    -f "$CHART/values-gha-${env_name}.yaml")"

  assert_absent() {
    if printf '%s' "$rendered" | grep -qE "$1"; then
      printf 'CHART[%s]: %s\n' "$env_name" "$2" >&2
      fail=1
    fi
  }
  assert_present() {
    if ! printf '%s' "$rendered" | grep -qE "$1"; then
      printf 'CHART[%s]: %s\n' "$env_name" "$2" >&2
      fail=1
    fi
  }

  assert_present '^  replicas: 1$' 'replicas must be exactly 1'
  assert_present '^    type: Recreate$' 'strategy must be Recreate, never RollingUpdate'
  # Anchored to the strategy line, NOT a bare 'RollingUpdate' match: helm
  # template passes template comments through to its output, and the
  # deployment's own comment explains why RollingUpdate is wrong. A bare match
  # fails on a correct chart. (Verified during execution.)
  assert_absent '^    type: RollingUpdate$' 'RollingUpdate would overlap two supervisors'
  assert_absent '^kind: Service$' 'the indexer must expose no Service'
  assert_absent 'containerPort' 'the indexer must expose no container port'
  assert_absent 'kind: SealedSecret' 'the chart must carry no secret material'
  assert_present 'readOnlyRootFilesystem: true' 'containers must be read-only-root'
  assert_present 'runAsNonRoot: true' 'containers must run as non-root'

  # The migrate initContainer and the app container must reference one image.
  local images distinct
  images="$(printf '%s' "$rendered" | grep -E '^ +image: ' | grep -v cloud-sql-proxy | sed 's/^ *image: *//' | sort -u)"
  distinct="$(printf '%s\n' "$images" | grep -c . || true)"
  if [ "$distinct" -ne 1 ]; then
    printf 'CHART[%s]: migrate and app containers must share one image, found:\n%s\n' \
      "$env_name" "$images" >&2
    fail=1
  fi
}

check_env test
check_env prod

if [ "$fail" -ne 0 ]; then
  printf 'CHART INVARIANTS FAILED\n' >&2
  exit 1
fi
printf 'chart invariants hold for test and prod\n'
```
